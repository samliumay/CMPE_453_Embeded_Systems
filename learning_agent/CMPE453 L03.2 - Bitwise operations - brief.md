## Known errors and traps in the sources (do not teach the errors)

- **Watch out:** `&`, `|`, `~` work on each bit. `&&`, `||`, `!` only answer true or false: `0x04 & 0x08` = 0 but `0x04 && 0x08` = 1. `!0x55` = 0.
- **Watch out:** - The slide's question mark: `PORTB.4 = 1;` is not C. `avr-gcc` rejects it. Write `PORTB |= (1<<4);`. - A test result for bit 5 is `0x20`, never 1. `if ((PINB & (1<<5)) == 1)` is never true. - `REG &= (1<<4);` clears the **other seven** bits. Clear with `~(1<<...
- **Slide bug in EX-3:** The slide says `if(PINB & 10000000)`. Without `0b` that is **decimal** ten million = `0x989680`. Its low byte is `0x80`, so the test still checks bit 7, by luck only. A leading 0 makes a constant **octal**: `00000010` is 8 = `0b00001000`, bit 3. `avr-gcc` warn...
- **Watch out:** `a |= b` changes `a`. `a != b` only asks "is a different from b?". `a = 5` writes, `a == 5` compares.
