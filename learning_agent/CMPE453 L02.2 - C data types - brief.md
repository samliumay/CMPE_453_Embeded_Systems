## Known errors and traps in the sources (do not teach the errors)

- **Watch out:** - Slide error: the table says `long` goes up to +2 147 483 648. Correct is +2 147 483 647 ($=2^{31}-1$). - On a PC `int` is 32 bits and `double` 64 bits. On the AVR `int` is 16 bits and `double` 32 bits (default `avr-gcc`). - Plain `char` is signed in `avr-gcc...
- **Watch out:** - `-Wall` gives no warning for `z <= 255`. `-Wextra` says "comparison is always true due to limited range of data type". Compile with `-Wall -Wextra`. - `z < 255` does end: it sends `0x00` to `0xFE`, 255 values. - The wrap rule is for unsigned types only. Sign...
- **Watch out:** - `0` is the number zero (`0x00`). `'0'` is one character (`0x30`). `"0"` is a string of two bytes (`0x30 0x00`). - `"012345ABCD"` has 10 visible characters but the array has 11 bytes: C adds a terminating `0x00`.
- **Watch out:** `~` flips 8 bits. `!` (logical NOT) gives only 0 or 1: `!0xAA` is `0`.
- **Watch out:** The LEDs cannot tell `0xFC` as `unsigned char` (252) from `0xFC` as `signed char` (−4). Only the type in the program decides.
- **Watch out:** - Each pass writes the port twice. The counter counts passes, not port changes. - `for(i=0; i<256; i++)` needs `unsigned int`: the counter must hold 256. - Slide typo: the comment "toggle PB 100,00 times" means 100 000.
- **The empty loop disappears:** With `-Os` (also used by the Arduino IDE) `avr-gcc` deletes the empty loop: `delay100ms` compiles to a single `ret`. Fix 1: `volatile unsigned int i;` (the loop stays, but our estimate is 52.7 ms, not 100 ms). Fix 2, better: `_delay_ms(100);`.
- **Errors on slide 11 (Exercise 8):** - Comment "delay in d microseconds": correct is **milliseconds**. - Comment "PORTA is output": correct is **PORTB**. The ATmega328P has no port A. - `delay_ms` is defined inside `main` (a nested function, not standard C) and passes a variable to `_delay_ms`. -...
