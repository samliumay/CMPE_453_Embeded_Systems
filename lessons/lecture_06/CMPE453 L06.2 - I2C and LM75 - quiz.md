## 1. Two wires and the timing rules (slides 2-3)

### Q1 (slide 2)

![[cmpe453_lecture_6_lecture6_2_p002.jpg]]

The figure shows an I2C bus: all devices share SDA and SCL, and R1, R2 connect the lines to Vcc. At the same moment device 1 wants a 1 on SDA and device 2 wants a 0. Which level is on SDA? And what happens if R1 is removed?

- A) High. Without R1 a released SDA floats, so no clean 1 can be sent.
- B) High. Without R1 the devices drive the 1 themselves, so SDA still works.
- C) Low. Without R1 a released SDA floats, so no clean 1 can be sent.
- D) Low. Without R1 the devices drive the 1 themselves, so SDA still works.

> [!success]- Answer
> **C.** An I2C pin is open-drain: it can only pull the line to GND or let go. Device 1 lets go, device 2 pulls low, so SDA is low. A 0 always wins.
> The 1 comes only from the pull-up R1. Without R1 a released line floats, so a 1 (and START, STOP, NACK) cannot be sent.
> - A: A 1 does not win. "Sending a 1" only means letting go, and device 2 still pulls the line low.
> - B: Both slips: the 1 does not win, and a device has no switch to Vcc, so it cannot drive a 1.
> - D: The level is right, but a device cannot drive a 1. Only R1 makes SDA high.

### Q2 (slide 3)

![[cmpe453_lecture_6_lecture6_2_p003.jpg]]

The figure shows SDA and SCL during one I2C transfer. What happens in the green bands (B0, B1, ..., BN)? And why are the yellow Start and Stop bands not data bits?

- A) Green: SCL is high, SDA is stable, the receiver reads the bit. Yellow: SDA changes while SCL is high.
- B) Green: SCL is high, the sender changes SDA to the next bit. Yellow: SDA changes while SCL is held low.
- C) Green: SCL is high, SDA is stable, the receiver reads the bit. Yellow: SDA changes while SCL is held low.
- D) Green: SCL is high, the sender changes SDA to the next bit. Yellow: SDA changes while SCL is high.

> [!success]- Answer
> **A.** Data is read only while SCL is high, so in the green bands SDA is stable and the receiver reads it. SDA changes in the blue bands, where SCL is low (the crossing lines).
> In the yellow bands SDA changes while SCL is high. A data bit never does that, so every device sees a control signal: falling SDA = START, rising SDA = STOP.
> - B: Both slips: SDA changes in the blue bands (SCL low), not in the green ones, and in the yellow bands SCL is high.
> - C: SDA changing while SCL is low is exactly what a normal data bit does. It would not mark a control signal.
> - D: The sender changes SDA only while SCL is low, in the blue bands. In the green bands SDA must stay stable.

## 2. Addresses and the read/write bit (slide 4)

### Q3 (slide 4)

An I2C address byte is (7-bit address `<< 1`) `|` R/W, with R/W = 0 for write (the master sends the next byte) and R/W = 1 for read (the slave sends the next byte). A display has the 7-bit address `0x3C`. Which are its write and read address bytes? The byte `0xA1` is seen on the bus as an address byte: which 7-bit address is it, and who sends the next data byte?

- A) Write `0x3C`, read `0x3D`. `0xA1`: address `0x50`, the master sends.
- B) Write `0x78`, read `0x79`. `0xA1`: address `0xA0`, the master sends.
- C) Write `0x3C`, read `0x3D`. `0xA1`: address `0xA0`, the slave sends.
- D) Write `0x78`, read `0x79`. `0xA1`: address `0x50`, the slave sends.

> [!success]- Answer
> **D.** `0x3C` = `0111100`. Shift left: `01111000` = `0x78`. Write: `0x78 | 0` = `0x78`. Read: `0x78 | 1` = `0x79`.
> `0xA1` = `10100001`. Bit 0 is 1: a read, so the slave sends. Address: `0xA1 >> 1` = `1010000` = `0x50`.
> - A: Two slips: the address is not shifted before the R/W bit is added, and "read" is taken from the slave's side. In a read the master reads and the slave sends.
> - B: `0xA0` only clears the R/W bit. The address also has to be shifted right by one. And in a read the slave sends.
> - C: The same missing shift in both directions: `0x3C` must be shifted left, `0xA0` right.

## 3. ACK or NACK (slide 5)

### Q4 (slide 5)

After every 8-bit byte comes a ninth bit, 0 = ACK, 1 = NACK. A master sends the read address of a slave and then reads 3 data bytes, and everything works. Who sends the ninth bit after each of the 4 bytes, with which value? How many SCL pulses do the 4 bytes need?

- A) Address: slave ACK. Data 1, 2, 3: master ACK. 32 pulses.
- B) Address: slave ACK. Data 1, 2: master ACK. Data 3: master NACK. 36 pulses.
- C) Address: slave ACK. Data 1, 2: master ACK. Data 3: master NACK. 32 pulses.
- D) Address: slave ACK. Data 1, 2, 3: master ACK. 36 pulses.

> [!success]- Answer
> **B.** The receiver of a byte sends the ninth bit. The slave receives the address and ACKs it. The master receives the data bytes: ACK for bytes 1 and 2 ("send more"), NACK for byte 3 ("this was the last one").
> Each byte needs 8 data bits + 1 acknowledge bit = 9 pulses: $4\cdot9=36$.
> - A: Two slips: the last byte gets a NACK on purpose, and $4\cdot8=32$ forgets the ninth bit of each byte.
> - C: The bits are right, but $4\cdot8=32$ forgets the acknowledge clock of each byte.
> - D: The count is right, but after the last byte the master sends NACK, not ACK. It is not an error, it ends the read.

## 4. A real conversation: the AVR reads an LM75 (slides 6-9)

### Q5 (slide 6)

The AVR wants to read the temperature from an LM75 sensor. It first sends one byte to the LM75 and then reads. Why must it send that byte? Not counting the address bytes, how many bytes go from the AVR to the LM75, and how many come back?

- A) The byte is a pointer: it selects the register the next read returns. One byte goes out, two come back.
- B) The byte starts a new measurement: the LM75 measures only on request. One byte goes out, one comes back.
- C) The byte starts a new measurement: the LM75 measures only on request. One byte goes out, two come back.
- D) The byte is a pointer: it selects the register the next read returns. One byte goes out, one comes back.

> [!success]- Answer
> **A.** The LM75 has more than one register (temperature, configuration, T_HYST, T_OS). The byte `00000000` is the pointer: it selects the temperature register for the next read.
> One byte goes to the LM75 (the pointer). Two bytes come back: the most significant byte, then the least significant byte.
> - B: Two slips: the LM75 measures by itself, the byte only selects a register, and the temperature needs two bytes (the half degree is in the second byte).
> - C: The count is right, but the byte does not start a measurement. It is the register pointer.
> - D: The reason is right, but one byte holds only whole degrees. The 0.5 °C bit is in a second byte.

### Q6 (slide 7)

The 7-bit address of an LM75 is `1001` followed by the levels on its pins A2, A1, A0, in this order (GND = 0, Vcc = 1). Address byte = (7-bit address `<< 1`) `|` R/W, with 0 = write. A second LM75 has A2 = 0, A1 = 1, A0 = 1. Give its 7-bit address and its write and read address bytes. The AVR addresses it for writing and the sensor answers: which 9 bits are on SDA right after START?

- A) `0x4E`, write `0x9C`, read `0x9D`. Bits `100111000`.
- B) `0x4B`, write `0x96`, read `0x97`. Bits `100101101`.
- C) `0x4B`, write `0x96`, read `0x97`. Bits `100101100`.
- D) `0x4E`, write `0x9C`, read `0x9D`. Bits `100111001`.

> [!success]- Answer
> **C.** `1001` + `011` = `1001011` = `0x4B`. Shift left: `10010110` = `0x96` (write). Read: `0x96 | 1` = `0x97`.
> On SDA: `1001011` (address), `0` (write), `0` (ACK: the LM75 pulls SDA low). Together `100101100`.
> - A: The pins are taken in the order A0, A1, A2: `1001` + `110` = `0x4E`. The ACK is right.
> - B: The address is right, but ACK is 0 (SDA pulled low). A 1 in the ninth bit is a NACK.
> - D: Both slips: the pins in the wrong order, and ACK written as 1.

### Q7 (slide 8)

The AVR reads the LM75 like this: START, write address `0x90` (R/W = 0), pointer byte, then "another start command", the read address `0x91` (R/W = 1), then the data. Why can it not start reading right after the pointer byte? And why a repeated START instead of a STOP followed by a new START?

- A) The LM75 needs a new START to load the selected register. A STOP would reset the LM75 pointer to 0.
- B) Only a new address byte can set R/W = 1. A STOP would reset the LM75 pointer to 0.
- C) The LM75 needs a new START to load the selected register. A repeated START keeps the bus from other masters.
- D) Only a new address byte can set R/W = 1. A repeated START keeps the bus from other masters.

> [!success]- Answer
> **D.** The conversation began with R/W = 0: the AVR sends. Only an address byte carries R/W, and an address byte must come right after a START. So the AVR sends START and `0x91`.
> A repeated START does this without a STOP, so the bus never becomes free. With only one master, STOP then START also works; it is only longer.
> - A: Both reasons are invented. The START is needed for the new R/W bit, and a STOP does not clear the pointer.
> - B: The first part is right, but a STOP does not reset the pointer. STOP then START would also work, only the bus is free in between.
> - C: The second part is right, but the START is not for loading a register. It is needed because only an address byte can change the direction.

### Q8 (slide 9)

The LM75 temperature is a 9-bit two's-complement number in steps of 0.5 °C: the 8 bits of the most significant byte (MSB) and bit 7 of the least significant byte (LSB). So the MSB holds the whole degrees (signed) and LSB bit 7 adds 0.5 °C. Convert: (a) MSB `00011110`, LSB `00000000`; (b) MSB `0xF5`, LSB `0x80`.

- A) (a) 15.0 °C, (b) −10.5 °C.
- B) (a) 30.0 °C, (b) −10.5 °C.
- C) (a) 30.0 °C, (b) 245.5 °C.
- D) (a) 15.0 °C, (b) 245.5 °C.

> [!success]- Answer
> **B.** (a) `0x1E00` = 7680, bit 15 is 0. $7680/128=60$, $T=60/2=30.0$ °C. (MSB = 30, LSB bit 7 = 0.)
> (b) `0xF580` = 62848, bit 15 is 1: $62848-65536=-2688$. $-2688/128=-21$, $T=-21/2=-10.5$ °C.
> Shortcut: `0xF5` signed is $245-256=-11$, plus 0.5 gives $-10.5$ °C.
> - A: (a) takes the MSB as the 9-bit number $N$ and halves it: $30/2=15$. But the MSB is already whole degrees.
> - C: (b) reads the MSB as unsigned: $245+0.5=245.5$. Bit 7 of the MSB is the sign, so the value is negative.
> - D: Both slips: the MSB halved in (a), and the MSB read as unsigned in (b).

## 5. The TWI registers (slide 10)

### Q9 (slide 10, bit rate)

$f_{SCL}=f_{CPU}/(16+2\cdot\text{TWBR}\cdot4^{\text{TWPS}})$, where `TWPS` is the value of the bits `TWPS1:0`. $f_{CPU}=16$ MHz. (a) `TWBR = 18` and `TWPS1:0 = 01`: what is $f_{SCL}$? (b) Which `TWBR` gives $f_{SCL}=50$ kHz with `TWPS1:0 = 00`?

- A) (a) 307.7 kHz, (b) `TWBR = 160`.
- B) (a) 307.7 kHz, (b) `TWBR = 152`.
- C) (a) 100 kHz, (b) `TWBR = 152`.
- D) (a) 100 kHz, (b) `TWBR = 160`.

> [!success]- Answer
> **C.** (a) `TWPS = 1`, so the prescaler is $4^1=4$: $f_{SCL}=16\,000\,000/(16+2\cdot18\cdot4)=16\,000\,000/160=100$ kHz.
> (b) $16\,000\,000/50\,000=320$ cycles per SCL period. $\text{TWBR}=(320-16)/(2\cdot1)=304/2=152$. It fits in 8 bits.
> - A: Two slips: prescaler 1 instead of $4^1$ gives $16\,000\,000/52=307.7$ kHz, and $320/2=160$ forgets the 16 fixed cycles.
> - B: (a) uses the bit value 1 as the prescaler instead of $4^1=4$: $16\,000\,000/(16+36)=307.7$ kHz.
> - D: (b) forgets to subtract 16: $320/2=160$ gives $16\,000\,000/336=47.6$ kHz, not 50 kHz.

### Q10 (slide 10, figure)

![[cmpe453_lecture_6_lecture6_2_p010.jpg]]

The figure shows the TWI module of the ATmega328P; the thick boxes are the registers a program can use. A program uses the AVR only as I2C master, like the LM75 thermometer. Which of these registers does it never need, and why?

- A) `TWAR`. It holds the AVR's own address, and only a slave must recognise its address.
- B) `TWBR`. The slave makes the clock on SCL, so a master needs no bit rate.
- C) `TWCR`. After `TWEN` is set, the master steps run by themselves.
- D) `TWDR`. The master puts the slave address into `TWAR` and never loads a byte.

> [!success]- Answer
> **A.** `TWAR` is in the Address Match Unit. Its comparator checks every address byte on the bus against the AVR's own address. Only a slave needs that.
> A master writes the address of the other device into `TWDR`, like any data byte.
> - B: The master makes SCL. The Bit Rate Generator uses `TWBR` to set its speed.
> - C: Every step (START, send, read, STOP) is a command written to `TWCR`. Nothing runs by itself.
> - D: The master sends the slave address and the pointer byte through `TWDR`, and reads the data from it. `TWAR` is not the target address.

## 6. The I2C library and the thermometer program (slides 11-12)

### Q11 (slide 11, read functions)

```c
uint8_t i2cReadAck(void) {
  TWCR = (_BV(TWINT) | _BV(TWEN) | _BV(TWEA));
  i2cWaitForComplete();
  return (TWDR);
}
uint8_t i2cReadNoAck(void) {
  TWCR = (_BV(TWINT) | _BV(TWEN));
  i2cWaitForComplete();
  return (TWDR);
}
```

`initI2C` has already set `TWEN` (TWI on) with `TWCR |= (1 << TWEN);`. The two functions differ in the bit `TWEA`. What does `TWEA` = 1 do on the bus? And why does every function still write `TWEN`?

- A) `TWEA` = 1: the AVR leaves SDA high after the byte (NACK). The hardware clears `TWEN` after each step.
- B) `TWEA` = 1: the AVR pulls SDA low after the byte (ACK). The hardware clears `TWEN` after each step.
- C) `TWEA` = 1: the AVR leaves SDA high after the byte (NACK). `TWCR = ...` overwrites all bits, so `TWEN` would become 0.
- D) `TWEA` = 1: the AVR pulls SDA low after the byte (ACK). `TWCR = ...` overwrites all bits, so `TWEN` would become 0.

> [!success]- Answer
> **D.** With `TWEA` = 1 the AVR pulls SDA low in the ninth clock: ACK, "send me more". With `TWEA` = 0 it leaves SDA high: NACK, "this was the last byte".
> `TWCR = ...` writes the whole register. A bit not in the value becomes 0, so without `_BV(TWEN)` the TWI would be switched off.
> - A: Both slips: ACK is the low level (0), and `TWEN` is not cleared by hardware. It is lost only because `=` overwrites it.
> - B: The ACK part is right, but the hardware does not clear `TWEN`. It is the `=` assignment that would clear it.
> - C: The `TWEN` part is right, but "enable acknowledge" means ACK, and ACK is SDA pulled low.

### Q12 (slide 11, i2cStop)

```c
void i2cWaitForComplete(void) {
  loop_until_bit_is_set(TWCR, TWINT);
}
void i2cStop(void) {
  TWCR = (_BV(TWINT) | _BV(TWEN) | _BV(TWSTO));
}
```

Every other function that writes `TWCR = ...` then calls `i2cWaitForComplete()`. The hardware sets `TWINT` when a step is finished. Why does `i2cStop` not wait?

- A) Waiting would keep SCL low, so the STOP could never reach the bus.
- B) After a STOP the hardware does not set `TWINT`, so the wait would never end.
- C) The STOP is made at once by the write, so `TWINT` is already set again.
- D) `TWINT` stays 1 after the write, so the wait would end at once and is useless.

> [!success]- Answer
> **B.** A STOP ends the conversation, so there is no next step to report and the hardware does not set `TWINT`. `loop_until_bit_is_set(TWCR, TWINT)` would wait forever and the program would hang. The hardware clears `TWSTO` when the STOP is done.
> - A: SCL is held low while `TWINT` is 1. The write of a 1 to `TWINT` clears it, so the bus is free to make the STOP. Polling does not change the bus.
> - C: A STOP takes bus time, and `TWINT` does not become 1 after it.
> - D: Writing a 1 to `TWINT` clears it to 0. It does not stay 1.

### Q13 (slide 12)

```c
i2cStart();
i2cSend(LM75_ADDRESS_W);
i2cSend(LM75_TEMP_REGISTER);
i2cStart();                        /* repeated START */
i2cSend(LM75_ADDRESS_R);
tempHighByte = i2cReadNoAck();     /* swapped */
tempLowByte = i2cReadAck();        /* swapped */
i2cStop();
printByte(tempHighByte);
if (tempLowByte & _BV(7)) {
  printString(".5\r\n");
}
else {
  printString(".0\r\n");
}
```

A student swaps the two read calls as shown. `i2cReadNoAck` sends a NACK after the byte, `i2cReadAck` an ACK. SDA has a pull-up to Vcc. At 21.5 °C the LM75 sends MSB `0x15` (21), then LSB `0x80`. What does the LM75 do after the first byte, and what is printed?

- A) It ignores the NACK and sends the LSB, so `tempLowByte = 0x80`. It prints `21.5`.
- B) It treats the NACK as an error and sends the MSB again, so `tempLowByte = 0x15`. It prints `21.0`.
- C) It stops sending and lets SDA go, so `tempLowByte = 0xFF`. It prints `21.5`.
- D) It waits for an ACK, so no new byte arrives and `TWDR` still holds `0x15`. It prints `21.0`.

> [!success]- Answer
> **C.** After the first byte the AVR sends a NACK: "stop sending". The LM75 lets go of SDA. When the AVR still clocks in a byte, the pull-up keeps SDA high, so the byte is most likely `0xFF` (expected bus behaviour, not tested on the board).
> Bit 7 of `0xFF` is 1, so it prints `21.5`. That is right only by luck: at 21.0 °C it would also print `21.5`.
> - A: A NACK from the master tells the slave transmitter to stop. The LM75 does not send the LSB.
> - B: A NACK from the master is not an error report, and the slave does not repeat a byte.
> - D: `i2cReadAck` still clocks in 8 new bits, so `TWDR` is overwritten with what is on SDA. The released line reads as 1s (pull-up), not the old `0x15`.
