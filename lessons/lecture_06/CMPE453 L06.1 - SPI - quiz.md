## 1. What SPI is (slide 2)

### Q1 (slide 2)

An SPI bus runs with SCK = 10 MHz. SPI moves one bit per clock pulse. A UART runs at 9600 baud with the 8N1 frame. How long does it take to send one byte over SPI, and one byte over the UART?

- A) SPI: 0.1 µs. UART: 1.042 ms.
- B) SPI: 0.8 µs. UART: 0.833 ms.
- C) SPI: 0.8 µs. UART: 1.042 ms.
- D) SPI: 0.1 µs. UART: 0.833 ms.

> [!success]- Answer
> **C.** SPI: 8 bits, one per clock: $8/10\,000\,000\ \text{s}=0.8\ \mu\text{s}$.
> UART 8N1: 1 start + 8 data + 1 stop = 10 bits: $10/9600\ \text{s}=1.042$ ms.
> The byte ratio is $1.042\ \text{ms}/0.8\ \mu\text{s}\approx 1302$, so "a thousand times faster" is true.
> - A: 0.1 µs is one clock period. A byte needs 8 clock pulses, not one.
> - B: 0.833 ms is $8/9600$ s. It forgets the start and stop bits of the UART frame.
> - D: Both slips: one clock for the whole SPI byte, and no start or stop bits for the UART.

## 2. The four pins (slides 3-4)

### Q2 (slide 3)

An SPI bus has four lines: MOSI (Master Out Slave In), MISO (Master In Slave Out), SCK and SS. Which lines does the slave drive (put the voltage on)?

- A) Only MISO.
- B) MISO and SCK.
- C) Only MOSI.
- D) MOSI and SS.

> [!success]- Answer
> **A.** MISO is "Slave **Out**": the slave drives it. The master drives MOSI ("Master **Out**"), SCK (it makes the clock) and SS (it selects the slave).
> So the slave drives only one line. The other three are inputs for the slave.
> - B: The master makes the clock. The slave only receives SCK, also when it answers.
> - C: MOSI is "Master Out". The "Out" belongs to the master, the slave only reads MOSI.
> - D: MOSI is a master output (see C), and SS is set by the master to select the slave.

### Q3 (slide 4)

On the Uno: SS = PB2/D10, MOSI = PB3/D11, MISO = PB4/D12, SCK = PB5/D13. A master must make SS, MOSI and SCK outputs. MISO and all other Port B pins stay inputs (a 1 in `DDRB` = output). Which value goes into `DDRB`?

- A) `0x28`
- B) `0x3C`
- C) `0x34`
- D) `0x2C`

> [!success]- Answer
> **D.** Outputs are bits 5 (SCK), 3 (MOSI) and 2 (SS):
> `(1<<5)|(1<<3)|(1<<2)` = `0b00100000 | 0b00001000 | 0b00000100` = `0b00101100` = `0x2C`. Bit 4 (MISO) stays 0.
> - A: `0x28` sets only bits 5 and 3. SS (PB2) is forgotten, as in the slide's own code.
> - B: `0x3C` also sets bit 4. Then MISO is an output and the master cannot receive.
> - C: `0x34` sets bits 5, 4, 2. MISO (PB4) was taken instead of MOSI (PB3).

## 3. The bus and the clock edges (slides 5-6)

### Q4 (slide 5)

![[cmpe453_lecture_6_lecture6_1_p005.jpg]]

In the figure the AVR master wants to talk to the DAC. Which level must the three slave-select lines have? What happens if two slaves are selected at the same time?

- A) DAC low, EEPROM and ADC high. Two selected slaves do no harm: both only read MOSI.
- B) DAC low, EEPROM and ADC high. Two selected slaves both drive MISO and the master reads garbage.
- C) DAC high, EEPROM and ADC low. Two selected slaves both drive MISO and the master reads garbage.
- D) DAC high, EEPROM and ADC low. Two selected slaves do no harm: both only read MOSI.

> [!success]- Answer
> **B.** SS is active low. The DAC's SS goes to 0, the other two stay at 1.
> A selected slave also drives the shared MISO wire. Two selected slaves drive it at the same time with different levels, so the master cannot read a valid bit.
> - A: The levels are right, but a selected slave also answers on MISO. Only MOSI would be harmless.
> - C: The effect is right, but SS is active low: high means "not selected".
> - D: Wrong level (SS is active low) and the MISO conflict is missed.

### Q5 (slide 6)

A student says: "First the master sends its 8 bits, then the slave answers with its 8 bits. So one byte exchange needs 16 clock pulses." How many clock pulses does one byte exchange (one byte each way) really need?

- A) 8 pulses: on each pulse both sides send one bit and receive one bit.
- B) 16 pulses: the statement is right, sending and answering take turns.
- C) 9 pulses: 8 pulses for the data and 1 pulse to select the slave.
- D) 4 pulses: each pulse has two edges, and each edge carries one bit.

> [!success]- Answer
> **A.** There is no "first send, then answer". On one edge both sides put out a bit, on the next edge both read a bit.
> So 8 pulses move one byte from master to slave and one byte from slave to master at the same time.
> - B: This is the mistake in the statement. SPI is full duplex: both directions use the same 8 pulses.
> - C: The slave is selected with the SS line, not with a clock pulse.
> - D: The two edges of a pulse do different jobs: one sets up the bit, the other samples it. One pulse = one bit.

## 4. The SPI module and SPCR (slides 7-10)

### Q6 (slide 7)

![[cmpe453_lecture_6_lecture6_1_p007.jpg]]

Three bit lines enter the "Select" block: `SPI2X`, `SPR1` and `SPR0`. `SPR1` and `SPR0` are bits 1 and 0 of `SPCR`. Follow the `SPI2X` line in the figure. In which register is `SPI2X`, and what does "Select" do?

- A) `SPI2X` is in `SPCR`, like the SPR bits. Select picks one divided clock as the master's SCK.
- B) `SPI2X` is in `SPSR`. Select sets the polarity and the phase of the SCK pulses.
- C) `SPI2X` is in `SPSR`. Select picks one divided clock as the master's SCK.
- D) `SPI2X` is in `SPCR`, like the SPR bits. Select sets the polarity and the phase of SCK.

> [!success]- Answer
> **C.** The `SPI2X` line comes from the SPI Status Register: `SPI2X` is bit 0 of `SPSR`.
> The Divider makes $f_{osc}/2$ to $f_{osc}/128$. Select uses the three bits to pick one of them as the "SPI Clock (Master)".
> - A: Select is right, but `SPI2X` is not in `SPCR`. All 8 bits of `SPCR` are already used.
> - B: The register is right, but polarity and phase are made in the "Clock Logic" block, from `CPOL` and `CPHA`.
> - D: Both parts are wrong: see A and B.

### Q7 (slide 8)

`SPCR` bits: `SPIE` = bit 7 (SPI interrupt enable), `SPE` = bit 6 (SPI enable), `MSTR` = bit 4 (1 = master, 0 = slave). A program writes `SPCR = 0xC0;`. Is the device a master or a slave? What else is needed before an SPI interrupt routine can run?

- A) A master. Still needed: `sei()` and an interrupt routine `ISR(SPI_STC_vect)`.
- B) A slave. Still needed: `sei()` and an interrupt routine `ISR(SPI_STC_vect)`.
- C) A master. Nothing else: `SPIE` = 1 is enough for the interrupt to run.
- D) A slave. Nothing else: `SPIE` = 1 is enough for the interrupt to run.

> [!success]- Answer
> **B.** `0xC0` = `0b11000000`: bits 7 (`SPIE`) and 6 (`SPE`) are 1. Bit 4 (`MSTR`) is 0, so the device is a slave.
> `SPIE` is only the local enable. The global enable `sei()` and the routine `ISR(SPI_STC_vect)` are also needed.
> - A: An enabled SPI is not a master by default. `MSTR` = 0 means slave.
> - C: Wrong role (see A), and `SPIE` alone does not let the interrupt run.
> - D: The role is right, but without `sei()` the interrupt never runs, and without the routine the program restarts.

### Q8 (slide 9)

`DORD` is bit 5 of `SPCR`: `DORD` = 1 means LSB first, `DORD` = 0 means MSB first. The sender has `SPDR` = `0x4B` and `DORD` = 1. The receiver wrongly uses `DORD` = 0. In which order do the bits appear on the line, and which byte does the receiver read?

- A) Line: 1, 1, 0, 1, 0, 0, 1, 0. The receiver reads `0x4B`.
- B) Line: 0, 1, 0, 0, 1, 0, 1, 1. The receiver reads `0xD2`.
- C) Line: 0, 1, 0, 0, 1, 0, 1, 1. The receiver reads `0x4B`.
- D) Line: 1, 1, 0, 1, 0, 0, 1, 0. The receiver reads `0xD2`.

> [!success]- Answer
> **D.** `0x4B` = `01001011` (bit 7 ... bit 0). LSB first sends bit 0, bit 1, ..., bit 7: 1, 1, 0, 1, 0, 0, 1, 0.
> The receiver with `DORD` = 0 takes the first bit as its bit 7: `11010010` = `0xD2`. The byte is bit-reversed.
> - A: The line is right, but the receiver's bit order matters: it puts the first bit at bit 7.
> - B: `DORD` was read the wrong way round on both sides. The byte is still reversed, but the line order is wrong.
> - C: `DORD` = 1 was read as MSB first, and the receiver's setting was ignored.

### Q9 (slide 10)

A sensor allows SCK of at most 400 kHz. The Uno has $f_{osc}$ = 16 MHz. With `SPI2X` = 0, `SPR1:SPR0` = 00, 01, 10, 11 give $f_{osc}/4$, $/16$, $/64$, $/128$. `SPI2X` = 1 halves each divider. Which is the fastest allowed setting, and how long does one byte take?

- A) `SPI2X` = 1, `SPR1` = 1, `SPR0` = 0. One byte takes 16 µs.
- B) `SPI2X` = 0, `SPR1` = 1, `SPR0` = 0. One byte takes 16 µs.
- C) `SPI2X` = 0, `SPR1` = 1, `SPR0` = 0. One byte takes 32 µs.
- D) `SPI2X` = 1, `SPR1` = 1, `SPR0` = 0. One byte takes 32 µs.

> [!success]- Answer
> **C.** The possible clocks are 8, 4, 2, 1 MHz, 500, 250 and 125 kHz. 500 kHz is too fast.
> The fastest one not above 400 kHz is $16\,000\,000/64=250$ kHz: `SPI2X` = 0, `SPR1:0` = 10 (`SPI2X` = 1, `SPR1:0` = 11 gives the same).
> One bit: $1/250\,000\ \text{s}=4\ \mu\text{s}$. One byte: $8\cdot 4\ \mu\text{s}=32\ \mu\text{s}$.
> - A: This is $f_{osc}/32$ = 500 kHz, the clock nearest to 400 kHz, but above the limit. Its byte time is $8/500\,000\ \text{s}=16\ \mu\text{s}$.
> - B: The setting is right, but one bit per edge was counted: $8/(2\cdot 250\,000)\ \text{s}=16\ \mu\text{s}$. SPI moves one bit per pulse.
> - D: 500 kHz is above the limit, and 32 µs counts 16 pulses per byte: $16/500\,000\ \text{s}$.

## 5. SPSR, SPDR and the data modes (slides 11-14)

### Q10 (slide 11)

`SPSR` bits: `SPIF` = bit 7, `WCOL` = bit 6 (write collision), `SPI2X` = bit 0 (double speed). A program reads `SPSR` and gets `0x81`. What does this say, and which of the three bits can the program write?

- A) A transfer is complete and double speed is on. The program can write only `SPI2X`.
- B) A transfer is complete and double speed is on. The program can write `SPIF` and `SPI2X`.
- C) A transfer is still running and double speed is on. The program can write only `SPI2X`.
- D) A transfer is still running and double speed is on. The program can write `SPIF` and `SPI2X`.

> [!success]- Answer
> **A.** `0x81` = `0b10000001`: `SPIF` = 1, `WCOL` = 0, `SPI2X` = 1.
> `SPIF` = 1 means a transfer is complete. No write collision. Double speed is on.
> The slide marks `SPIF` and `WCOL` R (read only) and `SPI2X` R/W. Only `SPI2X` can be written.
> - B: `SPIF` is read only. It is cleared by the hardware (read `SPSR`, then access `SPDR`), not by a write.
> - C: `SPIF` = 1 is the "done" flag, not a "busy" flag.
> - D: Both parts are wrong: see B and C.

### Q11 (slide 12)

A master on the Uno ($f_{osc}$ = 16 MHz) uses SCK = $f_{osc}/16$. It runs `SPDR = 0x7E;` and in the next line `x = SPDR;` with no wait. Why is `x` not the slave's answer, and how long does the transfer take?

- A) `x` reads back the byte just written, `0x7E`. The transfer takes 8 µs.
- B) Writing `SPDR` only starts the transfer. The transfer takes 0.5 µs.
- C) `x` reads back the byte just written, `0x7E`. The transfer takes 0.5 µs.
- D) Writing `SPDR` only starts the transfer. The transfer takes 8 µs.

> [!success]- Answer
> **D.** The write only starts the transfer. SCK = $16\ \text{MHz}/16=1$ MHz, so one bit takes 1 µs and one byte 8 µs (128 CPU cycles).
> The read comes a few CPU cycles later. The new byte has not arrived, so `x` holds the old received byte. Wait for `SPIF` = 1 first.
> - A: A read of `SPDR` returns the read buffer (the last received byte), not the byte just written.
> - B: 0.5 µs is $8/16\ \text{MHz}$: one bit per CPU clock. SCK is $f_{osc}/16$, not $f_{osc}$.
> - C: Both parts are wrong: see A and B.

### Q12 (slide 13)

A sensor datasheet says: "SCK is high when idle. Data is sampled on the rising edge." `SPCR` bits: `SPIE` = 7, `SPE` = 6, `DORD` = 5 (0 = MSB first), `MSTR` = 4, `CPOL` = 3 (1 = SCK high when idle), `CPHA` = 2 (0 = sample on the leading edge, 1 = on the trailing edge), `SPR1:0` = bits 1:0 (00 = $f_{osc}/4$). Which `SPCR` value makes the Uno a master for this sensor, MSB first, $f_{osc}/4$, no interrupt?

- A) `0x58`
- B) `0x5C`
- C) `0x50`
- D) `0x1C`

> [!success]- Answer
> **B.** Idle high: `CPOL` = 1. The clock leaves idle by falling, so the leading edge falls and the trailing edge rises.
> Sampling on the rising edge = trailing edge: `CPHA` = 1. Mode $2\cdot 1+1=3$.
> `SPCR` = `0x40 | 0x10 | 0x08 | 0x04` = `0b01011100` = `0x5C`.
> - A: `0x58` has `CPHA` = 0 (mode 2). It assumes the leading edge is always the rising one.
> - C: `0x50` has `CPOL` = 0 and `CPHA` = 0 (mode 0). It reads `CPOL` = 1 as "low when idle"; then rising is leading.
> - D: `0x1C` forgets `SPE` (bit 6). The SPI module stays off.

### Q13 (slide 14)

![[cmpe453_lecture_6_lecture6_1_p014.jpg]]

The diagram shows SCK for mode 0 (`CPOL` = 0) and mode 2 (`CPOL` = 1), both with `CPHA` = 0, and one SAMPLE line for both. On which edge does each mode sample the data?

- A) Mode 0: rising edge. Mode 2: rising edge.
- B) Mode 0: falling edge. Mode 2: rising edge.
- C) Mode 0: falling edge. Mode 2: falling edge.
- D) Mode 0: rising edge. Mode 2: falling edge.

> [!success]- Answer
> **D.** `CPHA` = 0 means sample on the leading edge, the first edge after idle.
> Mode 0 idles low, so its leading edge rises. Mode 2 idles high, so its leading edge falls.
> The leading edges of both clocks come at the same moments (the dashed lines). That is why one SAMPLE line is enough.
> - A: This reads `CPHA` = 0 as "sample on the rising edge". It means the leading edge, which depends on `CPOL`.
> - B: This samples on the trailing edge. That is `CPHA` = 1 (modes 1 and 3).
> - C: This reads `CPHA` = 0 as "sample on the falling edge". Mode 0 leaves idle low by rising.

## 6. Inside: shift registers (slides 15-17)

### Q14 (slide 15)

![[cmpe453_lecture_6_lecture6_1_p015.jpg]]

Master and slave each have an 8-bit shift register, connected by MOSI and MISO as in the figure. After 8 clocks they have swapped their bytes. What does each register hold if the master makes 16 clocks and nobody reloads the registers?

- A) Its own original byte: in 16 clocks each bit goes once around the 16-cell ring.
- B) The other side's byte: after the swap at 8 clocks, the bytes stay where they are.
- C) All zeros: each bit that leaves a register at the far end is lost for good.
- D) Its own byte bit-reversed: each bit comes back but enters at the opposite end.

> [!success]- Answer
> **A.** The two 8-bit registers form one ring of 16 cells. Each clock moves every bit one cell along the ring.
> After 8 clocks each bit sits in the same position in the other register. After 16 clocks it has gone once around and is back where it started.
> - B: The ring keeps turning with every clock. Clocks 9 to 16 swap the bytes back.
> - C: A bit that leaves one register on MOSI or MISO enters the other register. Nothing is lost.
> - D: Bits keep their order around the ring. After a full turn every bit is in its own cell, so nothing is reversed.

### Q15 (slide 16)

![[cmpe453_lecture_6_lecture6_1_p016.jpg]]

As on the slide, at each clock a new bit enters the leftmost cell and every bit moves one cell to the right. The register starts empty (`00000000`). The serial bits 0, 1, 1, 0 arrive in this order. What does the register hold after the 4th clock?

- A) `00000110`
- B) `11000000`
- C) `01100000`
- D) `00110000`

> [!success]- Answer
> **C.** One clock: new register = new bit, then the old first 7 cells.
> Clock 1 (0): `00000000`. Clock 2 (1): `10000000`. Clock 3 (1): `11000000`. Clock 4 (0): `01100000`.
> - A: The bits were entered on the right and shifted left. On the slide they enter on the left.
> - B: The 0 bits were skipped as if a 0 did not shift. A 0 also enters and moves the other bits.
> - D: One shift too many (5 clocks). There are 4 bits, so 4 clocks.

### Q16 (slide 17)

![[cmpe453_lecture_6_lecture6_1_p017.jpg]]

The example starts with the master register all ones and the slave register all zeros. The figure shows master `01111111` and slave `00000001`. How many clocks have passed? What do the registers hold 3 clocks after the figure?

- A) 7 clocks. Then master `00001111`, slave `00001111`.
- B) 1 clock. Then master `00001111`, slave `00001111`.
- C) 1 clock. Then master `11111000`, slave `11100000`.
- D) 7 clocks. Then master `11111000`, slave `11100000`.

## 7. SPI in C (slides 18-19)

### Q17 (slide 18, master)

The slide's master init writes `SPCR = (1<<SPE)|(1<<MSTR)|(1<<SPR0)|(1<<SPIE);`. Bits: `SPIE` = 7, `SPE` = 6, `MSTR` = 4, `SPR0` = 0. `SPI2X` stays 0 (reset value). With `SPI2X` = 0, `SPR1:SPR0` = 00, 01, 10, 11 give $f_{osc}/4$, $/16$, $/64$, $/128$, and $f_{osc}$ = 16 MHz. Which `SPCR` value and which SCK result?

- A) `SPCR` = `0x51`, SCK = 1 MHz
- B) `SPCR` = `0xD1`, SCK = 250 kHz
- C) `SPCR` = `0xD1`, SCK = 1 MHz
- D) `SPCR` = `0x51`, SCK = 250 kHz

> [!success]- Answer
> **C.** `0x40 | 0x10 | 0x01 | 0x80` = `0b11010001` = `0xD1`.
> `SPR1:SPR0` = 01 and `SPI2X` = 0: $f_{osc}/16=16\ \text{MHz}/16=1$ MHz. `CPOL` = `CPHA` = 0 gives mode 0, `DORD` = 0 gives MSB first.
> - A: `0x51` forgets the last term, `SPIE` (bit 7, `0x80`).
> - B: The value is right, but `SPR1:SPR0` was read as 10 ($f_{osc}/64$). `SPR0` is the low bit, so the pair is 01.
> - D: Both slips: see A and B.

### Q18 (slide 18, slave)

The slide's slave init is `DDRB = (1<<4);` and `SPCR = (1<<SPE);`. On the Uno MISO = PB4, `MSTR` is bit 4 of `SPCR` (0 = slave) and all `SPCR` bits are 0 after reset. Why is this enough for a slave?

- A) A slave drives only MISO (PB4) and gets SCK from the master, so `SPR1:0` do not matter.
- B) It is not enough: the slave must also make SCK (PB5) an output to clock its answer back.
- C) `MSTR` = 0 makes the slave copy the master's `SPR1:0` over SS, so it never sets them.
- D) It works only because the master also uses `SPR1:0` = 00, so both run at $f_{osc}/4$.

> [!success]- Answer
> **A.** The only line a slave drives is MISO = PB4, so only this pin must be an output.
> `MSTR` = 0 (the reset value) is the slave setting. A slave makes no clock: it follows SCK from the master, so `SPR1`, `SPR0` have no effect. Only `SPE` is needed: `SPCR` = `0x40`.
> - B: Only the master drives SCK. The slave sends its bits on MISO in step with the master's clock.
> - C: SS only selects the slave. Nothing is copied: the clock bits are simply not used in a slave.
> - D: The slave works with any master clock (up to $f_{osc}/4$). Its own `SPR` bits play no role.

### Q19 (slide 19)

The wait loop is `while (!(SPSR & (1<<SPIF)));`. `SPIF` is bit 7 of `SPSR`, `SPI2X` is bit 0. What is the loop condition for `SPSR` = `0x01` and for `SPSR` = `0x81`?

- A) `0x01`: FALSE, the loop ends. `0x81`: FALSE, the loop ends.
- B) `0x01`: TRUE, the loop waits. `0x81`: FALSE, the loop ends.
- C) `0x01`: FALSE, the loop ends. `0x81`: TRUE, the loop waits.
- D) `0x01`: TRUE, the loop waits. `0x81`: TRUE, the loop waits.

> [!success]- Answer
> **B.** `(1<<SPIF)` = `(1<<7)` = `0x80`.
> `0x01 & 0x80` = 0 and `!(0)` is TRUE: wait (`SPIF` = 0). `0x81 & 0x80` = 128 and `!(128)` is FALSE: stop (`SPIF` = 1).
> The mask keeps only bit 7, so `SPI2X` = 1 does not disturb the test. `while (SPSR == 0);` would stop at once for `0x01`.
> - A: This uses the mask `0x01`, as if `SPIF` were bit 0. Both values then give `!(1)` = FALSE.
> - C: This leaves out the `!`: `0x00` is FALSE and `0x80` is TRUE.
> - D: This reads `!` as the bitwise `~`: `~0x00` and `~0x80` are both non-zero, so both TRUE.
