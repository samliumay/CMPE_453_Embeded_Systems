# CMPE453 L05.1 - UART frame - quiz

Lesson note: [[CMPE453 L05.1 - UART frame]]. One question per check question of the lesson. Pick an option, then open the answer.

## 1. Serial communication and its three protocols (slides 2-3)

### Q1 (slide 2)

A device must move a block of 32 bytes. A parallel link with 8 data wires moves one whole byte every 50 µs. A serial link with 1 data wire moves one bit every 50 µs (count only the data bits, no start or stop bits). How long does each link need, and how many data wires does the serial link save?

- A) Parallel 1.6 ms, serial 12.8 ms; it saves 7 data wires.
- B) Parallel 1.6 ms, serial 1.6 ms; it saves 8 data wires.
- C) Parallel 0.2 ms, serial 12.8 ms; it saves 8 data wires.
- D) Parallel 0.2 ms, serial 1.6 ms; it saves 7 data wires.

> [!success]- Answer
> **A.** Parallel: one byte per step, $32\times 50\ \text{µs}=1600\ \text{µs}=1.6$ ms.
> Serial: $32\times 8=256$ bits, $256\times 50\ \text{µs}=12800\ \text{µs}=12.8$ ms. It is 8 times slower.
> The serial link needs 1 data wire instead of 8, so it saves 7 wires (and 7 pins).
> - B: Serial uses one step per byte, not per bit (forgot the factor 8): $32\times 50$ µs = 1.6 ms. And it forgets that the serial link still needs 1 wire: $8-1=7$, not 8.
> - C: Parallel divides the 32 bytes over the 8 wires: $32/8=4$ steps, $4\times 50$ µs = 0.2 ms. But each wire carries one bit of the byte, not a whole byte. And 8 wires saved forgets the 1 serial wire.
> - D: Both time mistakes: 0.2 ms (32 bytes divided over 8 wires) and 1.6 ms (forgot the factor 8 for the serial link).

### Q2 (slide 3)

The S and the A in USART stand for synchronous and asynchronous. Which extra wire does the synchronous mode need, and what replaces this wire when the AVR talks to a computer in asynchronous mode?

- A) A second data wire, so both sides can send at once. Both sides agree on the baud rate, and every byte begins with a start bit.
- B) A second data wire, so both sides can send at once. The receiver measures the length of each bit from the level changes.
- C) A clock wire (pin XCK) that says when to read each bit. Both sides agree on the baud rate, and every byte begins with a start bit.
- D) A clock wire (pin XCK) that says when to read each bit. The receiver measures the length of each bit from the level changes.

> [!success]- Answer
> **C.** Synchronous mode sends a clock on the XCK pin. The clock tells the receiver when to read each bit.
> Asynchronous mode has no clock wire. Both sides agree on the baud rate in advance, and the start bit of every byte tells the receiver when to start counting bit times.
> - A: A second data wire gives full duplex, not synchronous mode. The UART already has TX and RX and is still asynchronous.
> - B: Wrong wire (as in A), and the receiver does not measure bit lengths: equal bits in a row show no level change at all.
> - D: The wire is right, but the receiver cannot measure the bit time from the line. Three equal bits look like one long bit. The bit time must be agreed.

## 2. The protocol by hand: Elif sends 12 (slides 4-9)

### Q3 (slides 4-5)

![[cmpe453_lecture_05_1_lecture5_1_p004.jpg]]

In the circuit, the button connects the line to GND when pressed, $R_1$ connects the line to 5 V, and the LED goes from the line to GND. Somebody removes $R_1$. What does Damla see, and why does the protocol stop working?

- A) The LED stays on when released, because the line still reaches the LED. Only the start bit is lost.
- B) The LED is off when released and also off when pressed. 1 and 0 look the same, so no bit can be seen.
- C) The LED is off when released and on when pressed. 0 and 1 are swapped, so every byte arrives inverted.
- D) The line floats when released, so the LED flickers with noise. Damla reads random bits instead of the data.

> [!success]- Answer
> **B.** Without $R_1$ nothing connects the line to 5 V. Released, the line is not driven, no current flows, and the LED is off.
> Pressed, the line is at 0 V and the LED is off too. The LED never changes, so the idle 1 and the start edge (1 to 0) do not exist any more.
> - A: The LED needs a current from 5 V. Only $R_1$ gave this current, so the LED cannot stay on.
> - C: A press connects the line to GND (0 V). An LED to GND cannot light at 0 V.
> - D: An LED needs current, and a floating line delivers none. Noise does not light it; it stays off.

### Q4 (slide 6)

Elif sends 12 = `00001100` LSB first with a start bit 0 and a stop bit 1 (8 data bits). Slide 6 shows `Rcvd-bits = 0` after the first step. Is this 0 a bit of the number 12? Now suppose Elif forgets the start bit: she sends only the 8 data bits of 12 and then leaves the line idle at 1. Damla still expects a start bit, 8 data bits and a stop bit. Which byte does Damla decode?

- A) It is d0 of 12. Damla decodes `0x86` = 134.
- B) It is the start bit. Damla decodes `0x61` = 97.
- C) It is d0 of 12. Damla decodes `0x61` = 97.
- D) It is the start bit. Damla decodes `0x86` = 134.

> [!success]- Answer
> **D.** The first 0 is the start bit. It carries no data.
> Without a start bit the line shows `0 0 1 1 0 0 0 0`, then idle `1 1 ...`. Damla takes the first 0 as her start bit.
> Her d0..d7 are the next 8 line bits: `0 1 1 0 0 0 0 1`. Reversed, d7..d0 = `1000 0110` = `0x86` = 134.
> - A: The first received bit is always the start bit. d0 of 12 comes in the second step.
> - B: The data bits are not reversed: `01100001` read as written is `0x61` = 97. The first bit to arrive is d0, the rightmost digit.
> - C: Both mistakes: the start bit taken as d0, and the data bits not reversed.

### Q5 (slides 7-8)

On slides 6 to 8 the LED is off the whole time, for three bits in a row (bit time 1 s). How does Damla know that this is three bits and not one long bit? On a real line at 2400 baud the level stays low for 1.25 ms. How many bits is that?

- A) The line shows a short edge between two equal bits. 3 bits.
- B) Only by time: both sides agreed on the bit time. 12 bits.
- C) Only by time: both sides agreed on the bit time. 3 bits.
- D) The line shows a short edge between two equal bits. 12 bits.

> [!success]- Answer
> **C.** The line shows no border between equal bits. Damla knows the bit time (1 s), so 3 s of "off" means 3 bits.
> At 2400 baud one bit lasts $1/2400$ s = 416.7 µs. Number of bits: $1.25\ \text{ms}\times 2400\ \text{bits/s}=3$.
> - A: Equal bits in a row give one flat level. There is no edge between them.
> - B: 12 bits uses the 9600-baud bit time 104.2 µs: $1.25\ \text{ms}/104.2\ \text{µs}=12$. The line runs at 2400 baud.
> - D: Both mistakes: no edges exist between equal bits, and 12 uses the wrong baud rate (9600).

### Q6 (slide 9)

Elif sends 12 = `00001100` LSB first, after a start bit 0. After slide 9 Damla has `Rcvd-bits = 0001` (first bit first). Which bit of the byte is the 1, and what is it worth? What would Damla have after the same four steps if Elif sent 10 = `0000 1010`?

- A) The 1 is d3, worth 8. For 10: `Rcvd-bits = 0010`.
- B) The 1 is d2, worth 4. For 10: `Rcvd-bits = 0101`.
- C) The 1 is d3, worth 8. For 10: `Rcvd-bits = 0101`.
- D) The 1 is d2, worth 4. For 10: `Rcvd-bits = 0010`.

> [!success]- Answer
> **D.** The four received bits are start, d0, d1, d2. The 1 is d2, worth $2^2=4$.
> For 10: d0 = 0, d1 = 1, d2 = 0. With the start bit first: `0010`.
> - A: Counts the start bit as d0, so the 1 becomes d3. The start bit carries no data.
> - B: For 10 it forgets the start bit and lists d0..d3 = `0101`. The first received bit is always the start bit 0.
> - C: Both mistakes: the start bit counted as d0, and the start bit left out for 10.

## 3. The rest of the frame and decoding (slides 10-15)

### Q7 (slide 10)

Elif sends one 8N1 frame at 1 bit per second; the start edge (1 to 0) is at $t=0$. During d3 the LED is on, exactly as on an idle line. How does Damla know that this is a data bit, and during which time is d3 on the line?

- A) She counts bit times from the start edge, so the next 9 bits belong to the frame. d3 is on the line from 4 s to 5 s; she looks at 4.5 s.
- B) She cannot tell while it arrives; she decides when the stop bit comes. d3 is on the line from 4 s to 5 s; she looks at 4.5 s.
- C) She counts bit times from the start edge, so the next 9 bits belong to the frame. d3 is on the line from 3 s to 4 s; she looks at 3.5 s.
- D) She cannot tell while it arrives; she decides when the stop bit comes. d3 is on the line from 3 s to 4 s; she looks at 3.5 s.

> [!success]- Answer
> **A.** After the start edge every bit time belongs to the frame, whatever the level. Idle begins only after the stop bit.
> The start bit fills 0 s to 1 s. Bit d$i$ fills $(i+1)$ s to $(i+2)$ s, so d3 fills 4 s to 5 s. The middle is 4.5 s.
> - B: The stop bit is also 1, like idle, so it gives no extra sign. Damla knows by counting from the start edge.
> - C: Forgets that the start bit takes the first second. Then d3 would start at 3 s.
> - D: Both mistakes: no counting from the start edge, and the start bit's second left out.

### Q8 (slides 11-12)

A program gets bit $i$ of a byte with `(data >> i) & 1`. On the slides' line, 1 = LED on and 0 = LED off. Compute d4 and d5 for `data = 0x94` and say what the LED does for each.

- A) d4 = 0, LED off. d5 = 1, LED on.
- B) d4 = 1, LED on. d5 = 0, LED off.
- C) d4 = 1, LED off. d5 = 0, LED on.
- D) d4 = 0, LED on. d5 = 1, LED off.

> [!success]- Answer
> **B.** `0x94` = `1001 0100`.
> d4: `0x94 >> 4` = `0000 1001`, `& 1` gives 1. Line 1, LED on.
> d5: `0x94 >> 5` = `0000 0100`, `& 1` gives 0. Line 0, LED off.
> - A: Counts the bits from the left (MSB as bit 0): position 4 is 0 and position 5 is 1. Bit 0 is the rightmost bit.
> - C: The bits are right, but the LED is swapped. 1 = no press = LED on.
> - D: Both mistakes: bits counted from the left, and the LED swapped.

### Q9 (slides 13-14)

Elif sends 12 = `00001100`, 8N1, LSB first. The bits d4 to d7 are all 0, so she stops after d3 and sends the stop bit 1 right away. Then the line is idle at 1. Damla still expects 8 data bits. Which byte does she decode?

- A) `0x3F` = 63
- B) `0x1C` = 28
- C) `0x0C` = 12
- D) `0xFC` = 252

> [!success]- Answer
> **D.** Line: start `0`, d0..d3 = `0 0 1 1`, stop `1`, idle `1 1 1 ...`.
> Damla reads the stop bit and idle as d4..d7 = `1 1 1 1`; the next idle 1 is her stop bit.
> d7..d0 = `1111 1100` = `0xFC` = 252. Leading zeros must be sent too.
> - A: The data bits are not reversed: `00111111` read as written is `0x3F` = 63.
> - B: Takes the idle line as 0: d4 = stop bit 1, d5..d7 = 0, so `0001 1100` = 28. The idle line is 1.
> - C: Thinks the missing bits count as 0. Damla cannot know that bits are missing; she reads the line.

### Q10 (slide 15, decoding)

Damla records the 10 bits `0110010110` (first bit first). Decode them as slide 15 does (drop start and stop, reverse the 8 data bits). Is this a valid 8N1 frame?

- A) Not valid: the stop bit is 0. The data byte `0xD3` cannot be trusted.
- B) Not valid: the stop bit is 0. The data byte `0xCB` cannot be trusted.
- C) Valid: it starts with the start bit 0. The data byte is `0xD3`.
- D) Valid: it starts with the start bit 0. The data byte is `0xCB`.

> [!success]- Answer
> **A.** First bit 0: start bit correct. Last bit 0: the stop bit must be 1, so this is a framing error.
> Middle bits `11001011`, reversed `1101 0011` = `0xD3`. The byte cannot be trusted (wrong baud rate or format, or the receiver started inside a byte).
> - B: The middle bits are not reversed: `11001011` = `0xCB`.
> - C: Checks only the start bit. The stop bit must be 1 too.
> - D: Both mistakes: the stop bit not checked, and the data bits not reversed.

### Q11 (slide 15, timing)

A link runs at 57600 baud, 8N1 (1 start bit, 8 data bits, no parity, 1 stop bit). Give the bit time, the number of frames per second, and the time to send 1024 bytes without pauses.

- A) 1.736 µs, 5760 frames/s, 0.178 s
- B) 17.36 µs, 5760 frames/s, 0.178 s
- C) 17.36 µs, 7200 frames/s, 0.142 s
- D) 1.736 µs, 7200 frames/s, 0.142 s

> [!success]- Answer
> **B.** Bit time $1/57600$ s = $1.736\times 10^{-5}$ s = 17.36 µs. A frame has $1+8+1=10$ bits (173.6 µs).
> Frames per second: $57600/10=5760$.
> 1024 bytes: $1024\times 10=10240$ bits, $10240/57600$ s = 0.178 s.
> - A: Reads $1.736\times 10^{-5}$ s as 1.736 µs. 1 µs is $10^{-6}$ s, so it is 17.36 µs.
> - C: Counts 8 bits per frame (forgot start and stop): $57600/8=7200$, $1024\times 8/57600=0.142$ s.
> - D: Both mistakes: the power of ten in the bit time, and 8 bits per frame.

### Q12 (slide 15, baud mismatch)

The sender transmits one byte `0x3A` at 4800 baud, 8N1. The receiver is set to 9600 baud, 8N1. The line is idle (1) before and after the byte. The receiver starts counting at the 1-to-0 edge of the start bit and reads each bit in the middle of its own bit time. Which byte does the receiver decode first?

- A) `0x3A`
- B) `0x19`
- C) `0x98`
- D) `0xCC`

> [!success]- Answer
> **C.** The receiver's bit time (104.2 µs) is half the sender's (208.3 µs), so it reads every line bit twice.
> `0x3A` = `0011 1010`. Line: start `0`, d0..d7 = `0 1 0 1 1 1 0 0`, stop `1`.
> Doubled: `00 00 11 00 11 11 11 00 00 11`. The receiver's first 10: start `0`, data `0 0 0 1 1 0 0 1`, stop `1`.
> Reversed: d7..d0 = `1001 1000` = `0x98`.
> - A: The start bit only says when to begin. The receiver still counts its own, wrong bit time.
> - B: The receiver's data bits are not reversed: `00011001` read as written is `0x19`.
> - D: Doubles the data bits but not the start bit. The start bit lasts two receiver bit times too: `0 0 1 1 0 0 1 1` gives `0xCC`.

## 4. The USART in the ATmega328P and on the Uno (slides 16-18)

### Q13 (slide 16, data path)

![[cmpe453_lecture_05_1_lecture5_1_p016.jpg]]

The program writes `UDR0 = x;`. In the block diagram, which box turns the 8 parallel bits into a serial stream on TxDn, and which box decides how long each bit stays on the pin?

- A) UDRn (Transmit) sends the bits out; the Baud Rate Generator sets the bit time.
- B) The Transmit Shift Register sends the bits out; the Baud Rate Generator sets the bit time.
- C) UDRn (Transmit) sends the bits out; the TX Control block sets the bit time.
- D) The Transmit Shift Register sends the bits out; the TX Control block sets the bit time.

> [!success]- Answer
> **B.** The data bus writes all 8 bits into UDRn (Transmit) at once. The Transmit Shift Register shifts them out one by one, LSB first, with start and stop bits. It is the parallel-to-serial converter.
> The Baud Rate Generator divides the clock by a number from `UBRRn`. This sets the bit time.
> - A: UDRn (Transmit) is only the buffer that holds the byte. It does not shift.
> - C: Both wrong: UDRn is the buffer, and TX Control only turns the transmitter on. No clock goes into it.
> - D: TX Control only enables the transmitter. The clock for the shift register comes from the Baud Rate Generator.

### Q14 (slide 16, parity)

The byte `0x6B` = `0110 1011` is sent with even parity (8E1: start bit, 8 data bits LSB first, parity bit, 1 stop bit) at 19200 baud. Give the line bits, the number of whole frames per second, and the parity bit for odd parity.

- A) `0 11010110 1 1`; 1920 frames/s; odd parity bit 0.
- B) `0 11010110 0 1`; 1920 frames/s; odd parity bit 1.
- C) `0 11010110 0 1`; 1745 frames/s; odd parity bit 1.
- D) `0 11010110 1 1`; 1745 frames/s; odd parity bit 0.

> [!success]- Answer
> **D.** `0x6B` has five 1s (odd). Even parity: the total must be even, so the parity bit is 1.
> LSB first d0..d7 = `11010110`. Line: start `0`, data, parity `1`, stop `1` (11 bits).
> Frames per second: $19200/11=1745.45$, so 1745 whole frames. Odd parity: 5 is already odd, so the bit is 0.
> - A: Counts 10 bits per frame (forgot the parity bit): $19200/10=1920$.
> - B: Both mistakes: 10 bits per frame, and the even and odd rules swapped.
> - C: Swaps the rules: it picks the bit that makes the total odd for even parity (0), and the other one for odd parity (1).

### Q15 (slide 17)

![[cmpe453_lecture_05_1_lecture5_1_p017.jpg]]

A program on the Uno only sends text to the PC and receives nothing. Which of the two yellow-circled LEDs blinks, and which header pin carries the data? You measure this pin with a voltmeter while the program is silent. About which voltage do you read?

- A) The TX LED; pin D1 (TXD); about 5 V.
- B) The RX LED; pin D0 (RXD); about 5 V.
- C) The TX LED; pin D1 (TXD); about 0 V.
- D) The RX LED; pin D0 (RXD); about 0 V.

> [!success]- Answer
> **A.** The Uno transmits, so the TX LED blinks, and the data leaves on TXD = D1 (PD1).
> A silent line is idle, and idle is logic 1. The meter shows about 5 V.
> - B: Names the LED and pin from the PC's side (the PC receives). On the board, TX and D1 are the Uno's transmit side.
> - C: An idle UART line is 1, not 0. The start bit is the change to 0.
> - D: Both mistakes: the PC's view of RX and TX, and idle taken as 0 V.

### Q16 (slide 18)

![[cmpe453_lecture_05_1_lecture5_1_p018.jpg]]

A temperature logger only sends values from the AVR to the computer. The computer never answers. Which wires of the diagram are the minimum, and what kind of link is this? With both crossed wires connected, how many bytes per second can go each way at 9600 baud, 8N1?

- A) AVR RX (PD0) from adapter TX, and GND; simplex; 960 bytes/s each way.
- B) AVR RX (PD0) from adapter TX, and GND; half duplex; 480 bytes/s each way.
- C) AVR TX (PD1) to adapter RX, and GND; simplex; 960 bytes/s each way.
- D) AVR TX (PD1) to adapter RX, and GND; half duplex; 480 bytes/s each way.

> [!success]- Answer
> **C.** Data goes from the AVR out, so the needed wire is AVR TX (PD1) to adapter RX, plus GND. One direction only is simplex.
> With both crossed wires the link is full duplex: each direction has its own wire and carries $9600/10=960$ bytes/s at the same time.
> - A: The wire into the AVR's RX carries data from the computer to the AVR. The computer never sends.
> - B: Both mistakes: the wrong wire, and "half duplex" with the 960 bytes/s shared between the two directions ($960/2=480$).
> - D: One direction only is simplex. Half duplex means both directions on a shared wire. With separate wires, nothing is shared, so each way gets 960, not 480.
