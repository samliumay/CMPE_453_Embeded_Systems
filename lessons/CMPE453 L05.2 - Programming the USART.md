# CMPE 453 · Lecture 5.2 · Programming the USART

> [!summary] In short
> - Four steps: set the baud rate, enable TX/RX, to send wait for `UDRE0` then write `UDR0`, to receive wait for `RXC0` then read `UDR0`.
> - $\text{UBRR0}=f_{osc}/(16\,\text{BAUD})-1$ (normal) or $f_{osc}/(8\,\text{BAUD})-1$ (double speed, `U2X0` = 1), rounded.
> - Uno, 16 MHz, 9600 baud: `UBRR0` = 103. The slide's table is for 1 MHz.
> - `UCSR0B = 0x18` switches TX and RX on. `UCSR0C = 0x06` is 8N1.
> - The PC sends ASCII: `'5'` is `0x35`. Subtract `'0'` to get the number.

## 1. Four steps to use the UART (slide 2)
![[cmpe453_lecture_05_2_lecture5_2_p002.jpg]]

**Notes.**
1. **Set the baud rate** (`UBRR0H`, `UBRR0L`, and `U2X0` for double speed).
2. **Enable** transmission and/or reception (`TXEN0`, `RXEN0` in `UCSR0B`).
3. **To transmit**: wait until the UART is ready (`UDRE0` = 1), then load the data into `UDR0`.
4. **To receive**: check that data has arrived (`RXC0` = 1), then read it from `UDR0`.

You write the control bits. The hardware writes the flags.

## 2. Setting the baud rate: UBRR0 (slides 3-5)
![[cmpe453_lecture_05_2_lecture5_2_p003.jpg]]
![[cmpe453_lecture_05_2_lecture5_2_p004.jpg]]
![[cmpe453_lecture_05_2_lecture5_2_p005.jpg]]

**Notes.** $f_{osc}$ is the CPU clock in Hz. `UBRR0` is a whole number from 0 to 4095 (12 bits). Round to the nearest whole number.

| Mode | Baud rate | `UBRR0` value |
|---|---|---|
| Async normal (`U2X0` = 0) | $\dfrac{f_{osc}}{16(\text{UBRR0}+1)}$ | $\dfrac{f_{osc}}{16\,\text{BAUD}}-1$ |
| Async double speed (`U2X0` = 1) | $\dfrac{f_{osc}}{8(\text{UBRR0}+1)}$ | $\dfrac{f_{osc}}{8\,\text{BAUD}}-1$ |
| Synchronous master | $\dfrac{f_{osc}}{2(\text{UBRR0}+1)}$ | $\dfrac{f_{osc}}{2\,\text{BAUD}}-1$ |

After rounding, the real rate differs from the wanted one:

$$\text{error}=\left(\frac{\text{BAUD}_{\text{real}}}{\text{BAUD}_{\text{wanted}}}-1\right)\cdot100\,\%$$

Keep the error within about ±2 %. Always compute the real rate from the **rounded** `UBRR0`.

> [!example] Slide 4, at 1 MHz, 9600 baud
> - Normal: $10^6/(16\cdot9600)-1=5.51\to6$. Real: $10^6/(16\cdot7)=8928$. Error 7 % (too slow), not usable.
> - Double speed: $10^6/(8\cdot9600)-1=12.02\to12$. Real: $10^6/(8\cdot13)=9615$. Error 0.16 %, fine.

> [!example] The Uno, 16 MHz, 9600 baud
> $16\,000\,000/(16\cdot9600)-1=103.17\to103$. Real: $16\,000\,000/(16\cdot104)=9615.4$. Error +0.16 %.

`UBRR0L` holds bits 7..0, the low four bits of `UBRR0H` hold bits 11..8. Bits 15..12 are reserved. Split a value with `>> 8` (high byte) and `& 0xFF` (low byte). Example: 416 = `0x1A0`, so `UBRR0H = 0x01`, `UBRR0L = 0xA0`.

> [!warning] Watch out
> - **The slide's table is for a 1 MHz clock** and does not say so. At 16 MHz: 9600 → 103 (normal) or 207 (double), 4800 → 207 or 416, 2400 → 416 or 832.
> - The slide computes the error as (wanted − real)/wanted, which flips the sign. Its "0.15 %" is 0.16 %.
> - `UBRR0L = 416;` keeps only the low byte, 160.
> - The slide writes "UBBR0". The name is `UBRR0`.
> - "USART is sync communication and requires clock signal" holds only in synchronous mode. The asynchronous mode (UART) needs no clock wire.

## 3. Control and status registers (slides 6-9)
![[cmpe453_lecture_05_2_lecture5_2_p006.jpg]]
![[cmpe453_lecture_05_2_lecture5_2_p007.jpg]]
![[cmpe453_lecture_05_2_lecture5_2_p008.jpg]]
![[cmpe453_lecture_05_2_lecture5_2_p009.jpg]]

**Notes.**

| Register | Bit | Meaning when 1 |
|---|---|---|
| `UCSR0A` | 7 `RXC0` | a new byte is in `UDR0`, ready to be read. Reading `UDR0` clears it |
| `UCSR0A` | 5 `UDRE0` | `UDR0` is empty, new data can be loaded. Reset value 1 |
| `UCSR0A` | 1 `U2X0` | double speed mode (0 = normal) |
| `UCSR0B` | 4 `RXEN0` | receiver enabled, takes over PD0 as RxD |
| `UCSR0B` | 3 `TXEN0` | transmitter enabled, takes over PD1 as TxD |

`UDR0` (slide 7): the transmit buffer (TXB) and the receive buffer (RXB) share one I/O address. Writing `UDR0` loads TXB. Reading `UDR0` returns RXB.

Character size (slide 9): `UCSZ01:0` in `UCSR0C` and `UCSZ02` in `UCSR0B`.

| `UCSZ02` | `UCSZ01` | `UCSZ00` | Size |
|---|---|---|---|
| 0 | 0 | 0 | 5-bit |
| 0 | 0 | 1 | 6-bit |
| 0 | 1 | 0 | 7-bit |
| 0 | 1 | 1 | **8-bit** |
| 1 | 1 | 1 | 9-bit |

`UCSR0B = (1 << TXEN0) | (1 << RXEN0);` = `0b00011000` = `0x18`. `UCSR0C = (1 << UCSZ01) | (1 << UCSZ00);` = `0b00000110` = `0x06`, which is 8N1 and also the reset value.

> [!warning] Slide error
> The slide says for `RXC0`: "0 → data reception is in progress". Correct: `RXC0` = 0 means there is **no unread byte**. Usually nothing is arriving at all.

## 5. initUSART, transmitByte, receiveByte (slides 16-17)
![[cmpe453_lecture_05_2_lecture5_2_p016.jpg]]
![[cmpe453_lecture_05_2_lecture5_2_p017.jpg]]

**Notes.**

```c
#include <avr/io.h>
#include "USART.h"
#include <util/setbaud.h>
void initUSART(void)
{
  /* requires BAUD, defined in USART.h */
  UBRR0H = UBRRH_VALUE;                   /* defined in setbaud.h */
  UBRR0L = UBRRL_VALUE;
  /* select normal or double speed mode */
#if USE_2X
  UCSR0A |= (1 << U2X0);
#else
  UCSR0A &= ~(1 << U2X0);
#endif
  UCSR0B = (1 << TXEN0) | (1 << RXEN0);   /* enable USART transmitter/receiver */
  UCSR0C = (1 << UCSZ01) | (1 << UCSZ00); /* 8 data bits */
}
```

`<util/setbaud.h>` reads `F_CPU` and `BAUD` at compile time and defines `UBRRH_VALUE`, `UBRRL_VALUE` and `USE_2X` (1 if normal mode would miss the baud rate by more than 2 %). `BAUD` must be defined before the include. At 16 MHz and 9600 baud: `UBRR0H` = 0, `UBRR0L` = 103 = `0x67`, `U2X0` = 0.

```c
void transmitByte(uint8_t data)
{
  loop_until_bit_is_set(UCSR0A, UDRE0);   /* wait for empty transmit buffer */
  UDR0 = data;                            /* send data */
}
uint8_t receiveByte(void)
{
  loop_until_bit_is_set(UCSR0A, RXC0);    /* wait for incoming data */
  return UDR0;                            /* return register value */
}
```

Both functions **poll**: they wait in a loop on a flag. `receiveByte` waits forever if no byte comes.

> [!warning] Watch out
> - `transmitByte` waits for `UDRE0`, `receiveByte` waits for `RXC0`. Swapping them is a classic bug.
> - If `TXEN0` is not set, nothing appears on TxD.
> - The receive buffer holds only 2 bytes. If the program is busy for long (a `_delay_ms(1000)`), bytes are lost.

## 6. The same in the Arduino language (slide 18)
![[cmpe453_lecture_05_2_lecture5_2_p018.jpg]]

**Notes.** `Serial.begin(9600)` does what `initUSART` does. `Serial.available()` checks `RXC0`, `Serial.read()` reads the byte, `Serial.write()` sends one.

The sketch: a button on pin 8 (with pull-up) and an LED on pin 13. A received `'1'` switches the LED on, `'0'` switches it off. In every pass of `loop()` it sends `'0'` if the button is not pressed and `'1'` if it is pressed, so the terminal is flooded with characters.

Two Unos with this sketch, TX of each to RX of the other and GNDs joined, make the Elif-and-Damla link of [[CMPE453 L05.1 - UART frame]].

> [!warning] Watch out
> `if (data_rcvd == '1')` compares. `if (data_rcvd = '1')` assigns and is always true.

## 7. printString and the main program (slides 19-21)
![[cmpe453_lecture_05_2_lecture5_2_p019.jpg]]
![[cmpe453_lecture_05_2_lecture5_2_p020.jpg]]
![[cmpe453_lecture_05_2_lecture5_2_p021.jpg]]

**Notes.**

```c
void printString(const char myString[])
{
  uint8_t i = 0;
  while (myString[i]) {          /* strings end with a null character in C */
    transmitByte(myString[i]);
    i++;
  }
}
```

A C string ends with `'\0'` (value 0), which is "false", so the loop stops there.

```c
int main(void)
{
  char serialCharacter;
  initUSART();
  printString("Hello computer!\r\n");      /* to test */
  printString("This is AVR!\r\n");
  while (1) {
    serialCharacter = receiveByte();
    transmitByte(serialCharacter);
  }
  return 0;
}
```

To print a number, send its digits: `'0' + b / 100`, `'0' + (b / 10) % 10`, `'0' + b % 10`. `transmitByte(65);` shows `A`, not "65".

> [!warning] Watch out
> - End terminal lines with `"\r\n"`: carriage return (`0x0D`) and line feed (`0x0A`).
> - Slide 21's `#include <USART.c>` and the other library headers only work in the Arduino IDE with the library installed. With `avr-gcc`, compile `USART.c` alongside and include `"USART.h"`.

## 8. Turn on LED number n (slides 22-24)
![[cmpe453_lecture_05_2_lecture5_2_p022.jpg]]
![[cmpe453_lecture_05_2_lecture5_2_p023.jpg]]
![[cmpe453_lecture_05_2_lecture5_2_p024.jpg]]

**Notes.** The AVR asks the laptop for an index, reads it, and turns on that LED out of 6 LEDs on PD2 to PD7. If the index is less than 2 or greater than 7 it sends "out of range".

Clean version of slide 24:

```c
#include <avr/io.h>
#include "USART.h"
int main(void)
{
  char c;
  DDRD |= 0b11111100;                  /* LEDs on PD2..PD7 (Uno D2..D7) */
  initUSART();                         /* PD0 = RXD, PD1 = TXD */
  printString("Hello Laptop!\r\n");
  printString("This is AVR.\r\n");
  while (1) {
    printString("Enter a number, from 2 to 7 and I will "
                "turn on corresponding LED\r\n");
    c = receiveByte();
    transmitByte(c);                   /* echo, so the user sees the key */
    printString("\r\n");
    if ((c < '2') || (c > '7')) {      /* '2' = 0x32, '7' = 0x37 */
      printString("The number you entered is out of range\r\n");
    } else {
      PORTD = (1 << (c - '0'));        /* '5' -> 5 -> 0b00100000 */
    }
  }
}
```

Typing `3` sends `0x33`. $\texttt{0x33}-\texttt{0x30}=3$, `1 << 3` = `0b00001000`, so `PORTD` = `0x08`: the LED on D3.

> [!warning] Problems in the slide's version
> - It writes `LED_PORT = (1 << serialCharacter);` and then `PORTD = LED_PORT;`: a detour through another port. `PORTD = (1 << n);` is enough.
> - `DDRD = 0xff` also makes PD0 (RxD) an output. It works only because `RXEN0` overrides PD0.
> - `PORTD = LED_PORT;` is printed at the left margin but is inside the `else` braces.
> - `printString("\n")` misses the `\r`.
> - Serial Monitor set to "Newline": typing `5` and Enter sends `'5'` and `'\n'` (`0x0A`). The LED lights, then "out of range" is printed. Choose "No line ending".

## Key formulas and terms
| Term | Meaning / formula |
|---|---|
| `UBRR0` | normal $f_{osc}/(16\,\text{BAUD})-1$, double $f_{osc}/(8\,\text{BAUD})-1$, rounded, 12 bits in `UBRR0H`:`UBRR0L` |
| Error | $(\text{real}/\text{wanted}-1)\cdot100\,\%$, keep within ±2 % |
| Uno, 16 MHz | 9600 → 103 (+0.16 %), 19 200 → 51, 38 400 → 25 |
| `UCSR0A` | `RXC0` (b7) byte received, `UDRE0` (b5) ready to send, `U2X0` (b1) double speed |
| `UCSR0B` | `RXEN0` (b4) takes PD0, `TXEN0` (b3) takes PD1, both: `0x18` |
| `UCSR0C` | `UCSZ01:00` = 11 is 8 bits, `0x06` = 8N1 (reset value) |
| `UDR0` | write = send (TXB), read = received byte (RXB) |
| Send | wait for `UDRE0`, write `UDR0` |
| Receive | wait for `RXC0`, read `UDR0` |
| ASCII digit | `'0'` + n, back with `c - '0'` |

## Check yourself
> [!question]- 1. 16 MHz, 19 200 baud, normal mode: `UBRR0`, real rate, error, and the C statements.
> $16\,000\,000/(16\cdot19\,200)-1=51.08\to$ **51**. Real: $16\,000\,000/832=19\,230.8$. Error **+0.16 %**.
> ```c
> UBRR0H = 0;
> UBRR0L = 51;
> UCSR0A &= ~(1 << U2X0);
> ```

> [!question]- 2. 8 MHz, 115 200 baud: is normal or double speed acceptable?
> Normal: $3.34\to3$, real 125 000, error +8.51 %. Double: $7.68\to8$, real 111 111, error −3.55 %. **Neither** is within ±2 %. Use 38 400 (UBRR0 = 12, +0.16 %).

> [!question]- 3. Which clock does the slide's table (9600 → 5.5 normal, 12.02 double) assume? Give `UBRR0H`/`UBRR0L` for 2400 baud at 16 MHz, normal mode.
> $(5.5+1)\cdot16\cdot9600\approx$ **1 MHz**. At 16 MHz: $415.67\to416=$ `0x1A0`: `UBRR0H = 0x01`, `UBRR0L = 0xA0`.

> [!question]- 4. Give `UCSR0B` and `UCSR0C` in hex for transmitter and receiver on, 8N1.
> `UCSR0B` = `0b00011000` = **`0x18`**. `UCSR0C` = **`0x06`**.

> [!question]- 5. Find three mistakes: `UCSR0B = (1 << RXEN0);` in init, `loop_until_bit_is_set(UCSR0A, RXC0);` in `transmitByte`, `loop_until_bit_is_clear(UCSR0A, RXC0);` in `receiveByte`.
> (1) `TXEN0` is missing, the transmitter is off. (2) `transmitByte` must wait for `UDRE0`. (3) `receiveByte` must use `loop_until_bit_is_set` on `RXC0`, otherwise it returns at once with no byte.

> [!question]- 6. Explain: (a) the terminal shows garbage instead of "Hello". (b) Typing 5 and Enter lights LED 5 and then prints "out of range".
> (a) Baud-rate mismatch, or `F_CPU` does not match the real clock. (b) The monitor also sends `'\n'` (`0x0A`), which is below `0x32`.
