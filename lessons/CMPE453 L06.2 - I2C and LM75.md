# CMPE 453 · Lecture 6.2 · I2C: the two-wire interface (TWI)

> [!summary] In short
> - I2C (TWI) uses two wires shared by every device: SDA (data) and SCL (clock), pulled up to Vcc. One data wire means half duplex.
> - SDA changes only while SCL is low and is read while SCL is high. An SDA edge while SCL is high is START (falling) or STOP (rising).
> - Address byte = (7-bit address `<< 1`) `|` R/W, with 0 = write and 1 = read.
> - After every byte the **receiver** sends a ninth bit: 0 = ACK, 1 = NACK.
> - LM75: address `1001000`, write `0x90`, read `0x91`. MSB = degrees, LSB bit 7 = 0.5 °C.
> - $f_{SCL}=f_{CPU}/(16+2\cdot\text{TWBR}\cdot4^{\text{TWPS}})$. On the 16 MHz Uno `TWBR = 72` gives 100 kHz.

## 1. Two wires and the timing rules (slides 2-3)
![[cmpe453_lecture_6_lecture6_2_p002.jpg]]
![[cmpe453_lecture_6_lecture6_2_p003.jpg]]

**Notes.** I2C is a synchronous serial bus with two wires: **SCL** (serial clock) and **SDA** (serial data). Atmel calls its I2C hardware the 2-wire Serial Interface (**TWI**). On the Uno SDA = A4/PC4 and SCL = A5/PC5.

All devices connect to the same two wires. Two resistors pull SDA and SCL up to Vcc. A device can only pull a line **low**, so the idle bus is high.

The slide's question: there is only one data wire, so I2C is **half duplex**. The two sides take turns.

Timing rules (slide 3):
- A clock master controls the communication by sending the timing signal on SCL.
- The data line may change **only while the clock line is low**.
- Data is read **only while the clock line is high**.

The two exceptions are control signals:
- **START**: SDA goes from high to low while SCL is high.
- **STOP**: SDA goes from low to high while SCL is high.
- A START in the middle of a conversation, with no STOP before it, is a **repeated START**.

## 2. Addresses and the read/write bit (slide 4)
![[cmpe453_lecture_6_lecture6_2_p004.jpg]]

**Notes.** Several devices share the lines, so each device has a specific **7-bit address**. The **eighth bit** (R/W) says who sends next:
- START, address, then **0**: the slave is going to **receive** a byte from the AVR (write).
- START, address, then **1**: the slave **sends** data, the master reads it off the bus (read).

Recipe for the address byte: take the 7-bit address $a$, shift it left by one (`a << 1`), then write = `(a << 1) | 0`, read = `(a << 1) | 1`.

> [!example] LM75
> 7-bit address `1001000` = `0x48`. Write byte `0b10010000` = `0x90`. Read byte `0b10010001` = `0x91`.

> [!warning] Watch out
> - The slide says "Eight bit". It means the eighth bit of the address byte (bit 0, sent last).
> - Datasheets give addresses as 7-bit (`0x48`) or already shifted (`0x90`). Shifting twice, or not at all, is the most common reason why a device does not answer.

## 3. ACK or NACK (slide 5)
![[cmpe453_lecture_6_lecture6_2_p005.jpg]]

**Notes.** The **receiver** of a byte (master or slave) acknowledges it. A **ninth bit** is sent after every 8-bit byte:
- **0 (low) = ACK**: byte acknowledged, the sender may continue.
- **1 (high) = NACK**: there was an error, or the transmitter should stop sending, or the whole communication is about to end.

So a transmission error can be detected, for example in a noisy environment. In SPI everything is assumed to work.

A missing slave gives a NACK by itself: nobody pulls SDA low, the pull-up keeps it high.

> [!warning] Watch out
> A NACK is not always an error. The master sends a NACK on purpose after the last byte it wants to read.

## 4. A real conversation: the AVR reads an LM75 (slides 6-9)
![[cmpe453_lecture_6_lecture6_2_p006.jpg]]
![[cmpe453_lecture_6_lecture6_2_p007.jpg]]
![[cmpe453_lecture_6_lecture6_2_p008.jpg]]
![[cmpe453_lecture_6_lecture6_2_p009.jpg]]

**Notes.** The LM75 is a temperature sensor. The AVR first sends a byte to put it in temperature-reading mode, then receives two bytes (here 21.5 degrees).

The conversation on the oscilloscope trace:

| Step | On the bus | Who sends |
|---|---|---|
| 1 | START (SDA falls while SCL is high) | AVR |
| 2 | `1001000` + `0` (write) = `0x90` | AVR |
| 3 | ACK (0) | LM75 |
| 4 | `00000000` (pointer: temperature register) | AVR |
| 5 | ACK (0) | LM75 |
| 6 | repeated START | AVR |
| 7 | `1001000` + `1` (read) = `0x91` | AVR |
| 8 | ACK (0) | LM75 |
| 9 | `00010101` = 21, the most significant byte | LM75 |
| 10 | ACK (0) | AVR |
| 11 | `10000000`, the least significant byte | LM75 |
| 12 | NACK (1): end of the communication | AVR |
| 13 | STOP (SDA rises while SCL is high) | AVR |

For the cheap LM75 only the first bit (bit 7) of the low byte counts: it stands for half a degree. So `00010101` and `10000000` mean $21+0.5=21.5$ °C.

Full format (datasheet): the temperature is a 9-bit two's-complement number in units of 0.5 °C:

$$T=\frac{(\text{MSB}\ll8\;|\;\text{LSB})\gg7}{2}\ ^\circ\text{C}\quad(\text{signed shift})$$

## 5. The TWI registers (slide 10)
![[cmpe453_lecture_6_lecture6_2_p010.jpg]]

**Notes.**

| Register | Job |
|---|---|
| `TWCR` | control: you command a step |
| `TWSR` | status: bits 7-3 are the status code (`TWSR & 0xF8`), bits 1-0 `TWPS1:0` the prescaler (1, 4, 16, 64) |
| `TWBR` | bit rate, an 8-bit number for the SCL formula |
| `TWDR` | the byte to send, or the byte received |

`TWCR` bits: `TWINT` (b7) step finished, `TWEA` (b6) send ACK when receiving, `TWSTA` (b5) make a START, `TWSTO` (b4) make a STOP, `TWEN` (b2) TWI on, `TWIE` (b0) interrupt.

$$f_{SCL}=\frac{f_{CPU}}{16+2\cdot\text{TWBR}\cdot4^{\text{TWPS}}}\qquad\text{TWBR}=\frac{f_{CPU}/f_{SCL}-16}{2\cdot4^{\text{TWPS}}}$$

Standard speeds: 100 kHz and 400 kHz. At 16 MHz with prescaler 1: `TWBR = 72` gives $16\,000\,000/160=100$ kHz, `TWBR = 12` gives 400 kHz.

> [!warning] Watch out
> `TWINT` is cleared by writing a **1** to it, not a 0. The 1 means "go". While `TWINT` is 1, SCL is held low and the bus waits.

## 6. The I2C library and the thermometer program (slides 11-12)
![[cmpe453_lecture_6_lecture6_2_p011.jpg]]
![[cmpe453_lecture_6_lecture6_2_p012.jpg]]

**Notes.** Every step: (to send) put the byte in `TWDR`, write `TWCR` with `TWINT` = 1, `TWEN` = 1 and the extra bit for this step, wait until the hardware sets `TWINT` again, (to receive) read `TWDR`.

```c
void initI2C(void) {
  TWBR = 32;                      /* set bit rate, see p. 242 */
                                  /* 8MHz / (16+2*TWBR*1) ~= 100kHz */
  TWCR |= (1 << TWEN);            /* enable */
}
void i2cWaitForComplete(void) {
  loop_until_bit_is_set(TWCR, TWINT);
}
void i2cStart(void) {
  TWCR = (_BV(TWINT) | _BV(TWEN) | _BV(TWSTA));
  i2cWaitForComplete();
}
void i2cStop(void) {
  TWCR = (_BV(TWINT) | _BV(TWEN) | _BV(TWSTO));
}
uint8_t i2cReadAck(void) {
  TWCR = (_BV(TWINT) | _BV(TWEN) | _BV(TWEA));
  i2cWaitForComplete();
  return (TWDR);
}
uint8_t i2cReadNoAck(void) {
  TWCR = (_BV(TWINT) | _BV(TWEN));
  i2cWaitForComplete();
  return (TWDR);
}
void i2cSend(uint8_t data) {
  TWDR = data;
  TWCR = (_BV(TWINT) | _BV(TWEN));
  i2cWaitForComplete();
}
```

| Step | `TWCR` value |
|---|---|
| START | `TWINT\|TWEN\|TWSTA` = `0xA4` |
| send, or read with NACK | `TWINT\|TWEN` = `0x84` |
| read with ACK | `TWINT\|TWEN\|TWEA` = `0xC4` |
| STOP | `TWINT\|TWEN\|TWSTO` = `0x94` |

The event loop of the thermometer (slide 12), the same 13 steps as the trace:

```c
#define LM75_ADDRESS_W 0b10010000
#define LM75_ADDRESS_R 0b10010001
#define LM75_TEMP_REGISTER 0b00000000

i2cStart();
i2cSend(LM75_ADDRESS_W);
i2cSend(LM75_TEMP_REGISTER);
i2cStart();                        /* repeated START */
i2cSend(LM75_ADDRESS_R);
tempHighByte = i2cReadAck();
tempLowByte = i2cReadNoAck();
i2cStop();
printByte(tempHighByte);
if (tempLowByte & _BV(7)) {        //_BV(), defined in io.h
  printString(".5\r\n");
}
else {
  printString(".0\r\n");
}
_delay_ms(1000);                   /* Once per second */
```

> [!warning] Problems in the slide program
> - **The bit rate is for an 8 MHz chip** (the program comes from Williams' book). On the 16 MHz Uno `TWBR = 32` gives 200 kHz, not 100 kHz. It still works with the LM75. Use `TWBR = 72` for 100 kHz.
> - **No error checks.** `i2cSend` never looks at the ACK. If the LM75 is missing, the program prints junk as a temperature. Careful code checks `TWSR & 0xF8` after each step and sends a STOP on failure.
> - **Negative temperatures** print wrongly: `printByte` treats the MSB as unsigned, so −25 °C (`0xE7 0x00`) prints as `231.0`.
> - `tempLowByte && _BV(7)` (logical AND) would be true for any non-zero low byte. The test needs `&`.

## Key formulas and terms
| Term | Meaning / formula |
|---|---|
| Bus | SDA + SCL, pull-ups to Vcc, idle high, devices only pull low. Uno: A4/PC4, A5/PC5 |
| Timing | SDA changes while SCL is low, is read while SCL is high |
| START / STOP | SDA falls / rises while SCL is high |
| Frame | S, address (7) + R/W, A, data (8), A, ..., P. Sr = repeated START |
| Address byte | `(a << 1) \| 0` write, `(a << 1) \| 1` read |
| ACK / NACK | 9th bit from the receiver, 0 = ACK, 1 = NACK |
| LM75 | address `1001000`, W `0x90`, R `0x91`, pointer 0 = temperature, MSB = degrees, LSB bit 7 = 0.5 °C |
| SCL | $f_{CPU}/(16+2\cdot\text{TWBR}\cdot4^{\text{TWPS}})$. 16 MHz: 72 → 100 kHz, 12 → 400 kHz |
| One TWI step | write `TWCR = TWINT\|TWEN\|extra`, wait for `TWINT`, use `TWDR` |

## Check yourself
> [!question]- 1. I2C has one data wire and both sides may send on it. Half or full duplex? Why?
> **Half duplex.** One wire carries one level at a time, so the two sides take turns. Full duplex needs one wire per direction.

> [!question]- 2. SDA falls while SCL is high. What is it? And if SDA falls while SCL is low?
> While SCL is high: a **START**. While SCL is low: just a 0 bit being prepared.

> [!question]- 3. A sensor has the 7-bit address `0x48`. Give the address bytes for writing and reading.
> `0x48 << 1` = `0x90`. Write: **`0x90`**. Read: **`0x91`**.

> [!question]- 4. The LM75 returns `00010101` then `10000000`. What is the temperature? Who sends the ACK after the first byte and what follows the second?
> $21+0.5=$ **21.5 °C**. The AVR (the receiver) ACKs the first byte, then sends a NACK after the second and a STOP.

> [!question]- 5. `TWBR = 32`, prescaler 1. What is the SCL frequency at 8 MHz and at 16 MHz? Which `TWBR` gives 100 kHz at 16 MHz?
> 8 MHz: $8\,000\,000/(16+64)=$ **100 kHz**. 16 MHz: $16\,000\,000/80=$ **200 kHz**. For 100 kHz: $(160-16)/2=$ **72**.

> [!question]- 6. The LM75 is unplugged. What does the bus show after the address byte, and what does the slide program do?
> Nobody pulls SDA low in the ninth clock, so the master reads a **NACK**. The slide program does not check it and prints junk. Checked code sees the wrong status in `TWSR & 0xF8`, sends a STOP and reports an error.
