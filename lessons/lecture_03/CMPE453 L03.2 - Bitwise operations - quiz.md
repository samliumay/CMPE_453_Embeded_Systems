## 1. Bitwise logic operators (slides 2-3)

### Q1 (slide 2)

`x` is an 8-bit unsigned byte that holds `0x3A`. Bit 0 is the rightmost bit. The mask is `0xF0`, so it is 1 in the upper four bits (bits 7-4) and 0 in the lower four bits (bits 3-0). What are `x & 0xF0`, `x | 0xF0` and `x ^ 0xF0`?

- A) AND `0xFA`, OR `0x30`, XOR `0xFA`
- B) AND `0x30`, OR `0xFA`, XOR `0xFA`
- C) AND `0x30`, OR `0xFA`, XOR `0xCA`
- D) AND `0xFA`, OR `0x30`, XOR `0xCA`

> [!success]- Answer
> **C.** `x` = `0011 1010`, mask = `1111 0000`.
> AND: the upper bits meet 1 and are kept, the lower bits meet 0 and become 0: `0011 0000` = `0x30`.
> OR: the upper bits meet 1 and become 1, the lower bits are kept: `1111 1010` = `0xFA`.
> XOR: the upper bits meet 1 and are flipped, the lower bits are kept: `1100 1010` = `0xCA`.
> - A: This swaps AND and OR, and also computes XOR like OR (it gives the true OR value `0xFA`). AND with 0 clears, OR with 1 sets, XOR with 1 flips.
> - B: This computes XOR like OR. XOR with 1 flips the bit, it does not force a 1.
> - D: This swaps AND and OR: AND with 1 does not force a 1, it keeps the bit. AND gives `0x30`, OR gives `0xFA`.

### Q2 (slide 3)

All values are 8-bit unsigned bytes. Compute `0x9D & 0x3C`, `0x41 | 0x1A`, `0x6F ^ 0x33` and `~0x2B`, in this order.

- A) `0x1C`, `0x5B`, `0x5C`, `0xD4`
- B) `0xA1`, `0x5B`, `0x7F`, `0xD4`
- C) `0x1C`, `0x5B`, `0x7F`, `0xD5`
- D) `0xA1`, `0x5B`, `0x5C`, `0xD5`

> [!success]- Answer
> **A.** Write each byte as bits and apply the operator to each column.
> `1001 1101` & `0011 1100` = `0001 1100` = `0x1C`.
> `0100 0001` | `0001 1010` = `0101 1011` = `0x5B`.
> `0110 1111` ^ `0011 0011` = `0101 1100` = `0x5C`.
> `~0010 1011` = `1101 0100` = `0xD4`.
> - B: This mixes up two operators. The first value uses XOR instead of AND: `0x9D ^ 0x3C` = `0xA1`. The third uses OR instead of XOR: `0x6F | 0x33` = `0x7F`.
> - C: The third value uses OR instead of XOR (`0x7F`). The fourth is the negative number $-$`0x2B` = `0xD5` (two's complement). `~` only flips the bits, it does not add 1.
> - D: The first value uses XOR instead of AND (`0xA1`). The fourth is the two's complement $-$`0x2B` = `0xD5`, not `~0x2B`.

## 2. EX-1 and EX-2: set, clear and test one bit (slides 4-5)

### Q3 (slide 4)

`PORTB` is an 8-bit register. Bit n of `PORTB` is pin PBn (bit 0 is the rightmost bit). `PORTB` holds `0x6C`. The EX-1 loop runs these two lines:

```c
PORTB = PORTB | 0b00010000;  // set bit 4 (5th bit)
PORTB = PORTB & 0b11101111;  // clear bit 4 (5th bit)
```

What is `PORTB` after each line? A classmate writes `PORTB = 0b00010000; PORTB = 0b00000000;` instead. Bit 4 still toggles. What is wrong with it?

- A) `0x7C`, then `0x6C`. The `=` lines change only bit 4, but they run slower than `|` and `&`.
- B) `0x6C`, then `0x64`. The `=` lines write all 8 bits, so bits 6, 5, 3 and 2 are forced to 0.
- C) `0x6C`, then `0x64`. The `=` lines change only bit 4, but they run slower than `|` and `&`.
- D) `0x7C`, then `0x6C`. The `=` lines write all 8 bits, so bits 6, 5, 3 and 2 are forced to 0.

> [!success]- Answer
> **D.** `0x6C` = `0110 1100`. OR with `0001 0000` sets bit 4: `0111 1100` = `0x7C`.
> AND with `1110 1111` clears bit 4: `0110 1100` = `0x6C`. Only bit 4 moves.
> The classmate's `=` writes the whole byte: `PORTB` goes `0x10`, then `0x00`. Bits 6, 5, 3 and 2 were 1 and are lost.
> - A: The values are right, but a plain `=` writes all eight bits, not only bit 4.
> - B: This counts bit 4 from the left, so it works on bit 3. Bit 3 of `0x6C` is already 1, so OR gives `0x6C` and the clear gives `0x6C & 0xF7` = `0x64`.
> - C: The values count bit 4 from the left (bit 3, as in B), and a plain `=` writes all eight bits, not only bit 4.

### Q4 (slide 5)

All registers are 8-bit. Bit n of `PINB` is pin PBn and bit n of `PORTC` is pin PCn (bit 0 is the rightmost bit). The door sensor is on PB1, the LED on PC7. `PORTC` holds `0x15`. The EX-2 loop body is:

```c
if (PINB & 0b00000010)              // check pin 1 (2nd pin) of PINB
  PORTC = PORTC | 0b10000000;       // set pin 7 (8th pin)
else
  PORTC = PORTC & 0b01111111;       // clear pin 7 (8th pin)
```

What is `PORTC` after one pass, (a) when `PINB` reads `0x5A`, (b) when `PINB` reads `0xA5`?

- A) (a) `0x15`, LED off; (b) `0x15`, LED off
- B) (a) `0x95`, LED on; (b) `0x15`, LED off
- C) (a) `0x99`, LED on; (b) `0x19`, LED off
- D) (a) `0x7F`, LED on; (b) `0x7F`, LED on

> [!success]- Answer
> **B.** (a) `0101 1010` & `0000 0010` = `0000 0010` = `0x02`. Not zero, so true. `0x15 | 0x80` = `1001 0101` = `0x95`, LED on.
> (b) `1010 0101` & `0000 0010` = `0x00`, false. `0x15 & 0x7F` = `0001 0101` = `0x15`, LED off.
> - A: This treats the `if` as true only when the result is 1. The result in (a) is `0x02`, which is not zero, so the `if` is true.
> - C: This writes `0x15` as `0001 1001` (the digit 5 as `1001`). 5 is `0101`.
> - D: This treats the `if` as true only when the result is 1, so both cases take the `else` line, and it computes that line with OR: `0x15 | 0x7F` = `0x7F`. The code uses AND, and `0x02` is true.

## 3. EX-3 to EX-5: direction, copy a bit, toggle all (slides 6-8)

### Q5 (slide 6)

`PINB` is an 8-bit register. Bit n of `PINB` is pin PBn (bit 0 is the rightmost bit). A constant without a prefix is decimal, and only its lowest byte can meet the 8 bits of `PINB`. Someone writes `if (PINB & 1000000)` (one million). Which bit does this test, and which line is the correct test for bit 7?

- A) Bit 6. The correct test is `if (PINB & (1<<6))`.
- B) Bit 6. The correct test is `if (PINB & (1<<7))`.
- C) Bit 7. The correct test is `if (PINB & (1<<7))`.
- D) Bit 7. The correct test is `if (PINB & (1<<8))`.

> [!success]- Answer
> **B.** One million is `0xF4240`. Its low byte is `0x40` = `0100 0000`, so the line tests bit 6.
> The test for bit 7 is `if (PINB & (1<<7))`: `1<<7` = `0x80`.
> - A: The bit is right, but `(1<<6)` again tests bit 6. The task asks for bit 7.
> - C: This assumes the low byte is `0x80`, as for ten million (`0x989680`). For one million it is `0x40`.
> - D: This assumes the low byte is `0x80` (as in C) and counts bits from 1. The low byte is `0x40`, and `1<<8` = `0x100` has the low byte `0x00`, so that test is always false.

### Q6 (slide 7)

All registers are 8-bit. Bit n of `PINB` is pin PBn and bit n of `PORTC` is pin PCn (bit 0 is the rightmost bit). The task is to copy bit 5 of `PINB` to bit 7 of `PORTC`. `PINB` = `0x3C` and `PORTC` = `0x41`. EX-4 does:

```c
if (PINB & 0b00100000)
  PORTC = PORTC | 0b10000000;
else
  PORTC = PORTC & 0b01111111;
```

A classmate writes one line instead: `PORTC = PINB & 0b00100000;`. What is `PORTC` after the classmate's line, and after EX-4?

- A) Classmate `0x80`, EX-4 `0xC1`
- B) Classmate `0x61`, EX-4 `0x41`
- C) Classmate `0x20`, EX-4 `0x41`
- D) Classmate `0x20`, EX-4 `0xC1`

> [!success]- Answer
> **D.** `0x3C` = `0011 1100`, bit 5 is 1. `0011 1100` & `0010 0000` = `0x20`, so the classmate's line gives `0x20`.
> EX-4: the test is true, so `0x41 | 0x80` = `1100 0001` = `0xC1`.
> The one-liner has two mistakes: the 1 lands on bit 5, not bit 7, and the plain `=` deletes bits 6 and 0 of `PORTC`.
> - A: This assumes the 1 lands on bit 7. The AND keeps it at bit 5.
> - B: This assumes `=` keeps the old bits (like OR): `0x41 | 0x20` = `0x61`; a plain `=` overwrites all 8 bits. It also treats the EX-4 test as false because `0x20` is not 1.
> - C: This treats the test as false because `0x20` is not 1. Any non-zero value is true.

### Q7 (slide 8)

`PORTB` is an 8-bit register. Bit n of `PORTB` is pin PBn (bit 0 is the rightmost bit). `PORTB` holds `0x3C`. Give (a) `~PORTB`, (b) the mask that toggles only PB5 and PB0, and `PORTB` after `PORTB = PORTB ^ mask;` runs once and twice (from `0x3C`).

- A) `0xC3`; mask `0x21`; once `0x1D`, twice `0x3C`
- B) `0xC4`; mask `0x84`; once `0xB8`, twice `0x3C`
- C) `0xC4`; mask `0x21`; once `0x3D`, twice `0x3D`
- D) `0xC3`; mask `0x84`; once `0xBC`, twice `0xBC`

> [!success]- Answer
> **A.** (a) `0011 1100` flipped = `1100 0011` = `0xC3`.
> (b) A 1 at bit 5 and at bit 0: `0010 0001` = `0x21`.
> Once: `0011 1100` ^ `0010 0001` = `0001 1101` = `0x1D`. Twice: `0001 1101` ^ `0010 0001` = `0x3C`, the start value.
> - B: (a) is the negative number $-$`0x3C` = `0xC4`; `~` only flips the bits. The mask counts bits from the left (bit 5 from the left is bit 2, bit 0 from the left is bit 7): `0x84`, so `0x3C ^ 0x84` = `0xB8`.
> - C: (a) is the two's complement `0xC4` again. The toggle uses XOR like OR (set): `0x3C | 0x21` = `0x3D`, and again `0x3D`. XOR flips, so the second run gives `0x3C` back.
> - D: The mask counts bits from the left (`0x84`) and XOR is used like OR: `0x3C | 0x84` = `0xBC`, twice `0xBC`.

## 4. Compound assignment (slides 9-11)

### Q8 (slide 9)

`a` is an 8-bit unsigned variable that holds `0x5C`. The program runs `a &= 0x0F;` and then `a |= 0x90;`. What is `a` after each line, and what is the abbreviated form of `DDRB = DDRB & 0b11111011;`?

- A) `0x0C`, then `0x9C`; `DDRB != 0b11111011;`
- B) `0x5F`, then `0xDF`; `DDRB &= 0b11111011;`
- C) `0x0C`, then `0x9C`; `DDRB &= 0b11111011;`
- D) `0x5F`, then `0xDF`; `DDRB != 0b11111011;`

> [!success]- Answer
> **C.** `a &= 0x0F` is `a = a & 0x0F`: `0101 1100` & `0000 1111` = `0000 1100` = `0x0C`.
> `a |= 0x90` is `a = a | 0x90`: `0000 1100` | `1001 0000` = `1001 1100` = `0x9C`.
> `x = x & m` is written `x &= m`, so `DDRB &= 0b11111011;`.
> - A: `!=` is the comparison "is not equal". It does not change `DDRB`.
> - B: The first line uses OR instead of AND: `0x5C | 0x0F` = `0x5F`, then `0x5F | 0x90` = `0xDF`.
> - D: The first line uses OR instead of AND (`0x5F`, then `0xDF`), and `!=` is a comparison, not an assignment.

### Q9 (slide 10)

`DDRB` is an 8-bit register. Bit n of `DDRB` is pin PBn (bit 0 is the rightmost bit), and 1 means output. EX-6 is changed: it makes PB2 an input with `DDRB &= 0b11111011;`. Then, if PB2 is high, `DDRB &= 0b10111111;` makes PB6 an input, else `DDRB |= 0b01000000;` makes PB6 an output. `DDRB` is `0xFF` at the start. What is `DDRB` after the set-up line, after the `if` branch (PB2 high), and after the `else` branch that runs next (PB2 low)?

- A) `0xDF`, then `0xDD`, then `0xDF`
- B) `0xFB`, then `0xBF`, then `0x40`
- C) `0xDF`, then `0xFD`, then `0x02`
- D) `0xFB`, then `0xBB`, then `0xFB`

> [!success]- Answer
> **D.** Set-up: `1111 1111` & `1111 1011` = `1111 1011` = `0xFB`. The `if` only reads `PINB`.
> PB2 high: `1111 1011` & `1011 1111` = `1011 1011` = `0xBB`.
> PB2 low: `1011 1011` | `0100 0000` = `1111 1011` = `0xFB`.
> - A: This reads every binary literal in reverse order (`0b11111011` as `0xDF`, `0b10111111` as `0xFD`, `0b01000000` as `0x02`): `0xFF & 0xDF` = `0xDF`, `0xDF & 0xFD` = `0xDD`, `0xDD | 0x02` = `0xDF`. The rightmost digit is bit 0.
> - B: This treats `&=` and `|=` like `=`: `DDRB` becomes `0xFB`, then `0xBF`, then `0x40`. The compound forms keep the other bits.

### Q10 (slide 11)

`DDRB` is an 8-bit register. Bit n of `DDRB` is pin PBn (bit 0 is the rightmost bit), 1 means output, 0 means input. After reset `DDRB` is `0x00`. What is `DDRB` after `DDRB &= 0b11011111;`, what is it after `DDRB = 0b11011111;` instead, and why is the second line worse?

- A) `0xDF` and `0xDF`. Both lines give the same value, so neither is worse.
- B) `0x00` and `0xDF`. The plain `=` makes the other seven pins of port B outputs.
- C) `0x00` and `0xFB`. The plain `=` turns on the pull-ups of the other seven pins.
- D) `0xDF` and `0xDF`. Both lines make the other seven pins of port B outputs.

> [!success]- Answer
> **B.** With `&=`: `0000 0000` & `1101 1111` = `0x00`. PB5 is an input and the other pins stay inputs.
> With `=`: `DDRB` = `1101 1111` = `0xDF`. PB5 is an input too, but the other seven pins become outputs.
> The task only asks for bit 5. The plain `=` changes pins that other parts of the circuit may use as inputs.
> - A: This treats `&=` like `=`. The AND keeps the old 0 bits, so the result stays `0x00`.

> - D: This computes `&=` like `=` or `|=`, as in A. The AND keeps the old 0 bits, so the first line gives `0x00` and the other pins stay inputs.

## 5. Shift operators (slides 12-14)

### Q11 (slide 12)

All values are 8-bit unsigned. Compute `0b00101000 >> 2`, `0b00000110 << 4` and `1 << 6`.

- A) `0b10100000` (160), `0b01100000` (96), `0x20` (32)
- B) `0b00010100` (20), `0b00011000` (24), `0x40` (64)
- C) `0b00001010` (10), `0b01100000` (96), `0x40` (64)
- D) `0b00001010` (10), `0b00011000` (24), `0x20` (32)

> [!success]- Answer
> **C.** `>> 2` divides by $2^2=4$: $40/4 = 10$ = `0b00001010`.
> `<< 4` multiplies by $2^4=16$: $6\cdot16 = 96$ = `0b01100000`.
> `1 << 6` moves the 1 from bit 0 to bit 6: `0b01000000` = `0x40` = 64.
> - A: The first shift goes left instead of right: `0b00101000 << 2` = `0b10100000` = 160. The third counts bits from 1, so the 1 lands on bit 5: `0x20` = 32.
> - B: This divides and multiplies by $n$ instead of $2^n$: $40/2 = 20$ and $6\cdot4 = 24$.
> - D: The second value multiplies by $n=4$ instead of $2^4=16$ ($6\cdot4 = 24$), and the third counts bits from 1 (`0x20` = 32).

### Q12 (slide 13)

All values are 8-bit unsigned. D$n$ is bit $n$ (D0 is the rightmost bit). In the style of EX-8 the codes are (a) `(1<<6)`, (b) `~(1<<0)`, (c) `~(1<<7)`, (d) `(1<<6) | (1<<1)`. They give: (a) only a one in D6, (b) only a zero in D0, (c) only a zero in D7, (d) ones in D6 and D1 only. What are the four values in hex?

- C) `0x40`, `0xFE`, `0x80`, `0x00`
- D) `0x40`, `0xFF`, `0x7F`, `0x00`

> [!success]- Answer
> **A.** (a) `0100 0000` = `0x40`.
> (b) `1<<0` = `0000 0001`, flipped `1111 1110` = `0xFE`.
> (c) `1<<7` = `1000 0000`, flipped `0111 1111` = `0x7F`.

> - B: This forgets the `~` in (b) and (c): `0x01` and `0x80` have a single one, not a single zero.
> - C: This forgets the `~` in (c) (`0x80`), and joins the two bits of (d) with `&`: `0x40 & 0x02` = `0x00`. Two masks are joined with `|`.

### Q13 (slide 14)

On the Uno, pins 0 to 7 are PD0 to PD7 and pins 8 to 13 are PB0 to PB5. Bit n of `DDRx`, `PORTx` and `PINx` is pin Pxn (bit 0 is the rightmost bit). EX-9 is moved to the Uno: input on Uno pin 12, LED on Uno pin 7. Which port bits are these, and which test and clear lines are correct?

## 6. LED flow with `1 << i` (slides 15-17)

### Q14 (slide 15)

![[cmpe453_lecture_03_2_lecture3_2_p015.jpg]]

`blinkLEDs(byte)` writes the 8-bit value to `PORTD` and waits `DELAY` ms. Bit n of `PORTD` is LED n (bit 0 is the rightmost bit). One pass of `while(1)` makes the 15 calls on the slide: `0b10000000` down to `0b00000001`, then `0b00000010` up to `0b10000000`. The macro is changed to `#define DELAY 250`. How long is one pass, how long is LED 7 on at the turn between two passes, and what is the 4th call as `1 << n`?

- A) 4.0 s; 500 ms; `blinkLEDs(1 << 3)`
- B) 3.75 s; 250 ms; `blinkLEDs(1 << 3)`
- C) 4.0 s; 250 ms; `blinkLEDs(1 << 4)`
- D) 3.75 s; 500 ms; `blinkLEDs(1 << 4)`

> [!success]- Answer
> **D.** One pass has $8+7 = 15$ calls: $15\times250$ ms = 3750 ms = 3.75 s.
> A pass ends with `0b10000000` and the next pass starts with it, so LED 7 is on for $2\times250$ ms = 500 ms.
> The 4th call is `blinkLEDs(0b00010000)`. The 1 is at bit 4: `1 << 4`.
> - A: This counts $8+8 = 16$ calls ($16\times250$ ms = 4.0 s); the way back has only 7 calls. It also takes $n$ = call number minus 1; the 4th call from the top is bit 4 (7, 6, 5, 4).
> - B: This counts only one step for LED 7; the next pass starts with LED 7 again. It also takes $n$ = call number minus 1.
> - C: This counts 16 calls (4.0 s) and only one step for LED 7 at the turn.

### Q15 (slide 16)

`blinkLEDs` takes an 8-bit `uint8_t`, writes it to `PORTD` and waits 400 ms. Bit n of `PORTD` is LED n (bit 0 is the rightmost bit). `1 << 8` is `0x0100` as an `int`. Someone changes the first loop:

```c
for (i = 0; i <= 7; i++)   // right-to-left
  blinkLEDs(1 << i);
for (; i > 0; i--)        // left-to-right
  blinkLEDs(1 << i);
```

Which LEDs light in one pass, how many calls are there, and how long is the cycle?

- A) `0 1 2 3 4 5 6 7 (dark) 7 6 5 4 3 2 1`, 16 calls, 6.4 s
- B) `0 1 2 3 4 5 6 7 7 6 5 4 3 2 1`, 15 calls, 6.0 s
- C) `0 1 2 3 4 5 6 7 0 7 6 5 4 3 2 1`, 16 calls, 6.4 s
- D) `0 1 2 3 4 5 6 7 (dark) 7 6 5 4 3 2 1 0`, 17 calls, 6.8 s

> [!success]- Answer
> **A.** The first loop lights LEDs 0 to 7 and stops with $i = 8$.
> The second loop starts with $i = 8$. `1 << 8` = `0x0100`, and the `uint8_t` keeps only `0x00`: all LEDs are off for one step. Then $i = 7, \dots, 1$.
> Calls: $8+8 = 16$. Cycle: $16\times400$ ms = 6400 ms = 6.4 s.
> - B: This starts the second loop at $i = 7$. The first loop leaves $i = 8$.
> - C: This assumes the 1 of `1 << 8` wraps around to bit 0. It falls out of the byte, so the value is `0x00`.
> - D: The second loop stops when `i > 0` is false, so $i = 0$ never runs in it.

### Q16 (slide 17)

`blinkLEDs(byte)` writes the 8-bit value to `PORTD`. Bit n of `PORTD` is LED n (bit 0 is the rightmost bit). The slide 17 version is:

```c
for (i = 7; i > 0; i--)
  blinkLEDs(1 << i);
for (i = 0; i < 7; i++)
  blinkLEDs(1 << i);
```

Which LED is on during the 10th call of a pass, what is in `PORTD`, and can the second loop be written `for (; i < 7; i++)`?

- A) LED 1, `PORTD` = `0x02`; yes, the first loop leaves $i = 0$.
- B) LED 2, `PORTD` = `0x04`; yes, the first loop leaves $i = 0$.
- C) LED 2, `PORTD` = `0x02`; no, the first loop leaves $i = 1$.
- D) LED 1, `PORTD` = `0x02`; no, the first loop leaves $i = 1$.

> [!success]- Answer

> `PORTD` = `1 << 2` = `0b00000100` = `0x04`.
