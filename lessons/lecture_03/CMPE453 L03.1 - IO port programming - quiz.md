# CMPE453 L03.1 - IO port programming - quiz

Lesson note: [[CMPE453 L03.1 - IO port programming]]. One question per check question of the lesson. Pick an option, then open the answer.

## 1. The general structure of a program (slide 2)

### Q1 (slide 2)

An LED is on PD0. `DDRD` and `PORTD` are `0x00` after reset. Bit n of `DDRD` and of `PORTD` belongs to pin PDn (PD0..PD7, bit 0 is the rightmost bit). In `DDRD` a 1 bit makes the pin an output. On an input pin a 1 in `PORTD` only turns on the internal pull-up. The program is:

```c
int main(void) { while (1) { PORTD = 0x01; } DDRD = 0xFF; return (0); }
```

The LED stays dark (or glows only very weakly). Why?

- A) `while (1)` is false at the start, so `PORTD = 0x01;` never runs and PD0 stays at 0 V.
- B) `PORTD = 0x01;` sets bit 7, because bits are counted from the left, so PD7 goes high.
- C) `DDRD = 0xFF;` stands after the endless loop and never runs, so PD0 stays an input with the pull-up on.
- D) The loop runs once, then `DDRD = 0xFF;` makes PD0 an output, but `return (0);` stops the chip.

> [!success]- Answer
> **C.** `while (1)` never ends, so the lines after it are never reached. `DDRD` keeps `0x00` and PD0 is an input.
> `PORTD = 0x01;` then only turns on the pull-up of PD0. Only a very small current flows through it, so the LED is dark or very weak.
> Fix: `DDRD = 0xFF; while (1) { PORTD = 0x01; }`.
> - A: 1 is never 0, so `while (1)` is always true. The loop runs forever.
> - B: Bits are counted from the right, starting at 0. `0x01` is bit 0, that is PD0.
> - D: The loop never ends, so it does not "run once". `DDRD = 0xFF;` is never reached.

## 2. DDRx: the direction (slides 3-4)

### Q2 (slide 3)

`DDRC` is an 8-bit register. A 1 bit makes the pin an output, a 0 bit an input. Bit n of `DDRC` (bit 0 is the rightmost bit) belongs to pin PCn (PC0..PC7) and is called `DDCn`. After `DDRC = 0x15;`, which pins of port C are outputs?

- A) PC0, PC2 and PC4 (bits `DDC0`, `DDC2`, `DDC4`)
- B) PC3, PC5 and PC7 (bits `DDC3`, `DDC5`, `DDC7`)
- C) PC0, PC1, PC2 and PC3 (bits `DDC0` to `DDC3`)
- D) PC1, PC2 and PC4 (bits `DDC1`, `DDC2`, `DDC4`)

> [!success]- Answer
> **A.** `0x15` = `0001 0101` = `0b00010101`.
> Count from the right, starting at 0: the 1 bits are bit 0, bit 2 and bit 4. So PC0, PC2, PC4 are outputs.
> - B: This counts the bits from the left. Bit 0 is the rightmost bit.
> - C: This reads `0x15` as decimal 15 = `0b00001111`. The `0x` prefix means hexadecimal.
> - D: This writes the hex digit 5 as `0110`. 5 is `0101`, so the byte is `0b00010101`, not `0b00010110`.

### Q3 (slide 4)

`DDRD` is an 8-bit register, and bit n of `DDRD` (bit 0 is the rightmost bit) sets the direction of pin PDn (PD0..PD7). When a wider constant is written into it, only the lowest byte is kept. A student wants all of port D as output and writes `DDRD = 0x11111111;`. Which pins are really outputs, and what is the mistake?

- A) All eight pins. `0x11111111` is eight 1 bits, so the code is correct.
- B) Only PD0. Only the last digit 1 of the constant reaches `DDRD`.
- C) No pin. The constant is too large, so `DDRD` stays `0x00`.
- D) Only PD4 and PD0. The `0x` prefix makes it a 32-bit hex number.

> [!success]- Answer
> **D.** `0x` means hexadecimal. `0x11111111` is a 32-bit number. The lowest byte is `0x11` = `0b00010001`.
> Bits 4 and 0 are 1, so only PD4 and PD0 are outputs.
> Correct: `DDRD = 0b11111111;` or `DDRD = 0xFF;` or `DDRD = 255;`.
> - A: Eight 1 bits need the prefix `0b`. With `0x` each digit 1 is four bits, `0001`.
> - B: The lowest byte is two hex digits, `0x11`, not one digit. It has two 1 bits.
> - C: A too large constant is cut to its lowest byte. It is not dropped.

## 3. PORTx: the output value (slides 5-6)

### Q4 (slide 5)

Port B is an output port (`DDRB = 0xFF;`). Bit n of `PORTB` (bit 0 is the rightmost bit) sets the level of pin PBn (PB0..PB7). On the Uno, PB0 to PB5 are the digital header pins D8 to D13 (PB0 = D8, PB1 = D9, and so on). After `PORTB = 0x25;`, which pins are at Vcc?

- A) PB0, PB3 and PB4, that is D8, D11 and D12
- B) PB0, PB2 and PB5, that is D8, D10 and D13
- C) PB0, PB2 and PB5, that is D0, D2 and D5
- D) PB1, PB2 and PB5, that is D9, D10 and D13

> [!success]- Answer
> **B.** `0x25` = `0010 0101` = `0b00100101`. The 1 bits are bit 5, bit 2 and bit 0.
> So PB5, PB2, PB0 are at Vcc. With PB0 = D8: PB0 = D8, PB2 = D10, PB5 = D13.
> - A: This reads `0x25` as decimal 25 = `0b00011001`, bits 4, 3, 0.
> - C: The port pins are right, but PBn is not header pin Dn. Port B starts at D8.
> - D: This writes the hex digit 5 as `0110`. 5 is `0101`, so bit 0 is set, not bit 1.

### Q5 (slide 6)

Port D is an output port (`DDRD = 0xFF;`). The pin PDn is bit n of `PORTD`, and `PD5` = 5, `PD2` = 2. Which line gives `PORTD` a value with logic 1 on PD5 and PD2 and logic 0 on the other pins, written in four ways?

- A) `0b00100100` = `0x24` = 36 = `(1<<PD5) | (1<<PD2)`
- B) `0b00100100` = `0x24` = 24 = `(1<<PD5) | (1<<PD2)`
- C) `0b00100100` = `0x42` = 36 = `(1<<PD5) | (1<<PD2)`
- D) `0b00100100` = `0x24` = 36 = `(1<<PD5) & (1<<PD2)`

> [!success]- Answer
> **A.** Put a 1 under bit 5 and bit 2: `0b00100100`.
> Hex: `0010` = 2, `0100` = 4, so `0x24`. Decimal: $32+4=36$.
> Shifts: `(1<<PD5) | (1<<PD2)` = `0b00100000 | 0b00000100` = `0b00100100`.
> - B: This reads the hex digits `24` as a decimal number. `0x24` is $2\times16+4=36$.
> - C: This writes the two hex digits in the wrong order. The high nibble `0010` is the first digit: `0x24`. `0x42` would be 66.
> - D: `&` keeps only the bits set in both masks. They share no bit, so the result is 0.

## 4. PINx and the two output steps (slides 7-8)

### Q6 (slide 7)

Port B is an input port (`DDRB = 0x00;`). Bit n of `PINB` is 1 when pin PBn is at 5 V and 0 when it is at 0 V. PB4 and PB1 are at 5 V, all other pins at 0 V. What is `temp` after `temp = PINB;`?

- A) `0b00010010` = `0x12` = 12
- B) `0b01001000` = `0x48` = 72
- C) `0b00010010` = `0x12` = 18
- D) `0b11101101` = `0xED` = 237

> [!success]- Answer
> **C.** Bit 4 and bit 1 are 1: `0b00010010`.
> Hex: `0001` = 1, `0010` = 2, so `0x12`. Decimal: $16+2=18$.
> - A: This reads the hex digits `12` as a decimal number. `0x12` is $1\times16+2=18$.
> - B: This counts the bits from the left, so bit 4 and bit 1 land at positions 3 and 6.
> - D: This takes 5 V as 0 and 0 V as 1. A pin at 5 V gives a 1 bit.

### Q7 (slide 8)

Rules: bit n of `DDRB` and of `PORTB` belongs to pin PBn (PB0..PB7, bit 0 is the rightmost bit). In `DDRB` a 1 bit makes the pin an output, a 0 bit an input. On an output pin, bit n of `PORTB` sets the level (1 = Vcc, 0 = 0 V). On an input pin, a 1 in `PORTB` turns on the internal pull-up, a 0 leaves the pin floating. Both registers are `0x00` at the start. A student writes `PORTB = 0x20;` and then `DDRB = 0x20;`. What does PB5 do between the two lines, and after both lines?

- A) Between: output that drives Vcc. After: output that drives Vcc.
- B) Between: input with the pull-up on. After: output that drives Vcc.
- C) Between: floating input. After: output that drives Vcc.
- D) Between: input with the pull-up on. After: output that drives 0 V.

> [!success]- Answer
> **B.** `0x20` = `0b00100000` is bit 5.
> Between the lines: `DDB5` = 0 and `PB5` = 1. This is an input with the internal pull-up on.
> After both lines: `DDB5` = 1 and `PB5` = 1, so PB5 is an output that drives Vcc. This is the same end state as with the slide's order (DDR first, then PORT).
> - A: Between the lines `DDB5` is still 0, so PB5 is not an output yet.
> - C: `PB5` is already 1 between the lines. A floating input needs `PB5` = 0.
> - D: Writing `DDRB` does not change `PORTB`. `PB5` stays 1, so the output drives Vcc.

## 5. Two steps forward, one step back (slides 9-10)

### Q8 (slide 9)

An LED is wired pin → resistor → LED → GND. The pin gives 5 V and the LED takes about 2 V. The 1 kΩ resistor is replaced by a 220 Ω resistor. How much current flows through a lit LED, and is it below the 20 mA that a pin is normally loaded with?

- A) About 22.7 mA, so it is above 20 mA.
- B) About 9.1 mA, so it is below 20 mA.
- C) About 31.8 mA, so it is above 20 mA.
- D) About 13.6 mA, so it is below 20 mA.

> [!success]- Answer
> **D.** Voltage across the resistor: $5-2=3$ V.
> Ohm's law: $I=V/R=3/220\approx0.0136$ A $=13.6$ mA. This is below 20 mA.
> - A: This uses the full 5 V: $5/220\approx22.7$ mA. The LED takes 2 V of it.
> - B: This uses the LED voltage: $2/220\approx9.1$ mA. The resistor gets $5-2=3$ V.
> - C: This adds the voltages: $(5+2)/220\approx31.8$ mA. The LED voltage is subtracted.

### Q9 (slide 10)

![[cmpe453_lecture_03_1_lecture3_1_p010.jpg]]

In the slide's program `DDRD = 0xFF;`, bit n of `PORTD` (bit 0 is the rightmost bit) drives the LED on pin PDn (PD0..PD7), and each `blinkLEDs` call writes its byte to `PORTD` and then waits `DELAY` = 400 ms. Call $k$ runs from $(k-1)\times400$ ms to $k\times400$ ms. The lit bit goes 0, 1, 0, 1, 2, 1, 2, 3, 2, 3, 4, 3, 4, 5, 4, 5, 6, 5, 6, 7, 6, 7. Which LED is on at $t=6.1$ s, and which byte was written to `PORTD` for it?

- A) PD5, written as `PORTD` = `0x20`
- B) PD4, written as `PORTD` = `0x10`
- C) PD5, written as `PORTD` = `0x05`
- D) PD6, written as `PORTD` = `0x40`

> [!success]- Answer
> **A.** $6100/400=15.25$, so 15 calls are over and call 16 runs (6000 ms to 6400 ms).
> The 16th entry of the list is 5. Call 16 is `blinkLEDs(0b00100000);`, so `PORTD` = `0x20` and PD5 is on.
> - B: This takes call 15, the 15th entry 4. At 6.1 s call 15 is already over.
> - C: The LED is right, but the byte is the bit number 5. The byte has a 1 at bit 5: `0b00100000` = `0x20`.
> - D: This counts the list from entry 0, so it takes the 17th entry, 6.

## 6. Exercises 1 to 3 (slides 11-13)

### Q10 (slide 11)

Exercise 1 counts with `PORTB = PORTB + 1;` from `0x00` to `0xFF`, and then wraps to `0x00`. Each value now stays for `_delay_ms(100);`. Ignore the time of the other instructions. How long does one full count from `0x00` to `0xFF` take, and for how long is bit 7 of `PORTB` 1 during it?

- A) 25.5 s in total, bit 7 is 1 for 12.7 s
- B) 25.5 s in total, bit 7 is 1 for 12.8 s
- C) 25.6 s in total, bit 7 is 1 for 12.7 s
- D) 25.6 s in total, bit 7 is 1 for 12.8 s

> [!success]- Answer
> **D.** One full count has 256 values (0 to 255): $256\times100=25600$ ms $=25.6$ s.
> Bit 7 is 1 for `0x80` to `0xFF`, that is 128 to 255: $255-128+1=128$ values. $128\times100=12800$ ms $=12.8$ s.
> - A: This counts $255-0=255$ values and $255-128=127$ values. Both counts miss the +1.
> - B: The bit-7 count is right, but the full count misses the value 0: there are 256 values.
> - C: The total is right, but $255-128=127$ misses the +1. 128 to 255 are 128 values.

### Q11 (slide 12)

Exercise 2: `DDRB = 0x00; DDRC = 0xFF; while (1) { temp = PINB; PORTC = temp; }`. A student writes `temp = PORTB;` instead of `temp = PINB;`. All registers are `0x00` after reset, and the program never writes `PORTB`. The switches on port B give `0xA5`. Take port C as a full 8-bit port. What appears on port C?

- A) `0xA5`, because `PORTB` and `PINB` both hold the pin levels
- B) `0xFF`, because an input port reads all 1 bits in `PORTB`
- C) `0x00`, because `PORTB` still holds its reset value
- D) `0x5A`, because `PORTB` holds the inverted pin levels

> [!success]- Answer
> **C.** `PORTB` holds what the program wrote into it. The program never writes `PORTB`, so it is still `0x00`.
> The pin levels `0xA5` are only in `PINB`. Fix: read the input from `PINB`.
> - A: `PORTB` is the output value register. Only `PINB` holds the pin levels.
> - B: `PORTB` is not changed by the direction. It stays at its reset value 0.
> - D: `PORTB` does not depend on the pins at all, inverted or not.

### Q12 (slide 13)

Exercise 3: `DDRC = 0; DDRB = 0xFF; DDRD = 0xFF;` then in the loop `temp = PINC; if (temp < 100) PORTB = temp; else PORTD = temp;`. `PORTB` and `PORTD` start at `0x00`. `PINC` reads `0x50`, then `0x7F`, then `0x63`. What are (`PORTB`, `PORTD`) after pass 1, pass 2 and pass 3?

- A) (`0x50`, `0x00`), (`0x7F`, `0x00`), (`0x63`, `0x00`)
- B) (`0x50`, `0x00`), (`0x50`, `0x7F`), (`0x63`, `0x7F`)
- C) (`0x50`, `0x00`), (`0x00`, `0x7F`), (`0x63`, `0x00`)
- D) (`0x00`, `0x50`), (`0x7F`, `0x50`), (`0x7F`, `0x63`)

> [!success]- Answer
> **B.** Convert each byte to decimal and compare with 100.
> Pass 1: `0x50` $=80<100$, so `PORTB = 0x50`. Pass 2: `0x7F` $=127$, not below 100, so `PORTD = 0x7F`.
> Pass 3: `0x63` $=6\times16+3=99<100$, so `PORTB = 0x63`. The port that is not written keeps its old value.
> - A: This reads 100 as hex `0x100` = 256, so every byte goes to `PORTB`. The constant 100 is decimal.
> - C: This clears the port that is not written. A register keeps its value until it is written.
> - D: This swaps the branches: bytes below 100 go to `PORTD`, the others to `PORTB`.
