# CMPE 453 · Lecture 3.1 · I/O port programming

> [!summary] In short
> - Program shape: preamble (includes, macros, globals, functions), then `main`: configuration once, then `while(1)` forever.
> - Each port (B, C, D) has three registers: `DDRx` = direction, `PORTx` = output value, `PINx` = pin level.
> - `DDRx`: 1 = output, 0 = input. All pins are inputs after reset.
> - Output in two steps: `DDRx = mask;` then `PORTx = value;`. Inputs are read from `PINx`, never from `PORTx`.
> - On an input pin, `PORTxn = 1` turns on the internal pull-up.
> - ATmega328P: no port A, port C has only PC0-PC6.

## 1. The general structure of a program (slide 2)
![[cmpe453_lecture_03_1_lecture3_1_p002.jpg]]

**Notes.** The preamble prepares names and helpers. The main method configures the chip once and then loops forever.

```c
/* ---------- preamble ---------- */
#include <avr/io.h>          // include files
#include <util/delay.h>
#define DELAY 400            // macros
uint8_t count = 0;           // global variables
void show(uint8_t v)         // function definitions
{
    PORTD = v;
    _delay_ms(DELAY);
}
/* ---------- main method ---------- */
int main(void)
{
    DDRD = 0xFF;             // chip configuration (runs once)
    while (1) {              // infinite event loop (runs forever)
        show(count);
        count++;
    }
    return (0);              // never reached
}
```

A microcontroller has no operating system to return to, so the event loop must be infinite. `while(1)` loops forever because 1 is never 0 (0 means false). `return (0);` is never reached.

> [!question]- Check (slide 2): Find the bug. An LED is on PD0. `int main(void) { while (1) { PORTD = 0x01; } DDRD = 0xFF; return (0); }` The LED stays dark (or glows only very weakly). Why?
> The chip configuration is in the wrong place. `DDRD = 0xFF;` stands after the infinite loop, so it is never reached, just like `return (0);`.
> `DDRD` keeps its reset value `0x00`, so PD0 is still an input. `PORTD = 0x01;` then only switches on the pull-up of PD0, it does not drive the pin as an output.
> The pull-up is a large resistor inside the chip (about 20 to 50 kΩ, beyond the slides). Only about 0.1 mA can flow through it, far less than the 3 mA of a driven pin, so the LED is dark or only glows very weakly.
> Fix: put the configuration first, then the loop: `DDRD = 0xFF; while (1) { PORTD = 0x01; }`.

## 2. DDRx: the direction (slides 3-4)
![[cmpe453_lecture_03_1_lecture3_1_p003.jpg]]
![[cmpe453_lecture_03_1_lecture3_1_p004.jpg]]

**Notes.** `DDRx` is the Data Direction Register of port $x$, one bit per pin. A bit set to **1** makes the pin an **output**, **0** makes it an **input**. Readable and writable. Default after reset: all 0, every pin is an input. The names come from `<avr/io.h>`. The bits are named `DDxn`: `DDB5` is bit 5 of `DDRB` (the name is just the number 5).

| `DDRB` | `DDB7` | `DDB6` | `DDB5` | `DDB4` | `DDB3` | `DDB2` | `DDB1` | `DDB0` |
|---|---|---|---|---|---|---|---|---|
| bit | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |

All of port D as output, three ways to write the same byte:

```c
DDRD = 0xFF;          // hexadecimal
DDRD = 0b11111111;    // binary
DDRD = 255;           // decimal
```

> [!example] From pins to a value
> PB0, PB3, PB5 outputs, the rest inputs: put a 1 under each output pin: `0b00101001` = `0x29` = $32+8+1=41$. So `DDRB = 0x29;`.
> `DDRD = 0xF0;` is `0b11110000`: PD4-PD7 are outputs, PD0-PD3 inputs.

> [!warning] Watch out
> Count bits from the **right**, starting at 0. `=` overwrites all 8 bits. Single-bit changes need `|=` and `&=` ([[CMPE453 L03.2 - Bitwise operations]]).

> [!question]- Check (slide 3): After `DDRC = 0x15;`, which pins of port C are outputs? Give the names of the bits that are 1.
> Write the byte in binary: `0x15` = `0001 0101` = `0b00010101`.
> Count from the right, starting at 0: the 1 bits are bit 0, bit 2 and bit 4.
> So PC0, PC2 and PC4 are outputs. The bits are named `DDC0`, `DDC2`, `DDC4`. All other port C pins stay inputs (bit = 0).
> As a decimal number: $16+4+1=21$.

> [!question]- Check (slide 4): A student wants all of port D as output and writes `DDRD = 0x11111111;`. Which pins are really outputs, and what is the mistake?
> The prefix is wrong. `0x` means hexadecimal, so `0x11111111` is a 32-bit number, not eight binary digits.
> `DDRD` has only 8 bits, so only the lowest byte is kept: `0x11` = `0b00010001`.
> Only PD4 and PD0 are outputs, the other six pins stay inputs.
> Correct: `DDRD = 0b11111111;` or `DDRD = 0xFF;` or `DDRD = 255;`.

## 3. PORTx: the output value (slides 5-6)
![[cmpe453_lecture_03_1_lecture3_1_p005.jpg]]
![[cmpe453_lecture_03_1_lecture3_1_p006.jpg]]

**Notes.** `PORTx` sets the logic values on a port already configured as output. A bit set to **1** puts Vcc (5 V on the Uno) on the pin, **0** puts ground. Readable and writable, default 0. The bits are named `Pxn`: `PB3` is bit 3 of `PORTB`.

Slide example: port C as output, logic 1 on PC3 and PC6.

```c
DDRC  = 0xFF;          // Port C is output
PORTC = 0b01001000;    // logic 1 on PC6 and PC3
```

`0b01001000` = `0x48` = $64+8=72$. The same value with shifts: `(1<<PC6) | (1<<PC3)` = `0b01000000 | 0b00001000` = `0b01001000`.

Recipe for a list of pins: draw 8 boxes numbered 7 to 0, put a 1 under every pin in the list, read it as binary, convert to hex if wanted. Example: `PORTD = 0xA2;` is `0b10100010`: PD7, PD5, PD1 high.

> [!warning] Watch out
> - "1 puts Vcc on the pin" holds only for an **output** pin. On an input pin a 1 in `PORTx` switches on the pull-up.
> - The ATmega328P has no PC7. On the Uno PC6 is the RESET pin, so in the slide example only PC3 (A3) goes high. Use PC0-PC5 on a Uno.

> [!question]- Check (slide 5): Port B is already an output port (`DDRB = 0xFF;`). After `PORTB = 0x25;`, which pins are at Vcc, and which Uno header pins are these?
> `0x25` = `0010 0101` = `0b00100101`. The 1 bits are bit 5, bit 2 and bit 0.
> So PB5, PB2 and PB0 are at Vcc (5 V on the Uno). All other port B pins are at ground.
> On the Uno PB0-PB5 are the digital pins 8-13, so PB0 = D8, PB2 = D10, PB5 = D13.

> [!question]- Check (slide 6): Same task as the slide, but for port D: make port D an output port and drive logic 1 on PD2 and PD5. Give the value in binary, hex, decimal and with shifts.
> Step 1, direction: `DDRD = 0xFF;`
> Step 2, value: put a 1 under bit 5 and bit 2: `PORTD = 0b00100100;`
> Hex: `0010` = 2, `0100` = 4, so `0x24`. Decimal: $32+4=36$.
> With shifts: `(1<<PD5) | (1<<PD2)` = `0b00100000 | 0b00000100` = `0b00100100`.

## 4. PINx and the two output steps (slides 7-8)
![[cmpe453_lecture_03_1_lecture3_1_p007.jpg]]
![[cmpe453_lecture_03_1_lecture3_1_p008.jpg]]

**Notes.** If a port is configured as input, the logic level on each pin is available in `PINx`. On the slides `PINx` is read only.

```c
unsigned char temp;
DDRB = 0x00;     // Port B is input
temp = PINB;     // temp now holds the 8 pin levels of Port B
```

| Register | Question it answers |
|---|---|
| `DDRx` | which way: output or input? |
| `PORTx` | what to say: the value you write |
| `PINx` | what is there: the level the pin has now |

The four combinations for one pin:

| `DDRxn` | `PORTxn` | The pin |
|---|---|---|
| 1 | 0 | output, drives 0 V |
| 1 | 1 | output, drives Vcc |
| 0 | 0 | input, floating: reads noise if nothing is connected |
| 0 | 1 | input with internal pull-up: reads 1 if nothing is connected |

Using a port as output (slide 8): (1) write the `DDR` register, (2) write the value into the `PORT` register. Keep this order.

> [!warning] Watch out
> Read inputs from `PINx`. Reading `PORTx` gives back what you wrote, not what is on the pins.

> [!info] From pin levels to a number, and the order of the two steps (beyond the slides)
> Slide 7 only says that the input data "is made available in `PINx`". This is what it means:
> - Bit $n$ of `PINx` is 1 if pin $n$ is at 5 V, and 0 if it is at 0 V. The 8 pin levels together form one byte.
> - Example: PB5 and PB0 are at 5 V, all other port B pins at 0 V. Then `temp = PINB;` gives `0b00100001` = `0x21` = $32+1=33$.
> - `DDRB = 0x00;` is already the reset value. The line is still written, so that the direction is clear to the reader and does not depend on earlier code.
>
> Slide 8 gives the order DDR, then PORT. The other order (PORT first) also ends in the same state, but between the two lines the pin is still an input, so a 1 in `PORTx` only switches on its pull-up for that moment. Keep the slide's order.

> [!question]- Check (slide 7): Port B is an input port (`DDRB = 0x00;`). PB4 and PB1 are at 5 V, all other pins at 0 V. What is `temp` after `temp = PINB;`? Give binary, hex and decimal.
> Each pin level becomes one bit of `PINB`: 5 V gives 1, 0 V gives 0.
> Bit 4 and bit 1 are 1: `temp` = `0b00010010`.
> Hex: `0001` = 1, `0010` = 2, so `0x12`. Decimal: $16+2=18$.

> [!question]- Check (slide 8): A student writes the two steps in the other order: `PORTB = 0x20;` then `DDRB = 0x20;`. What does PB5 do between the two lines, and what does it do after both lines?
> Between the lines: `DDB5` is still 0 and `PB5` is 1. From the table of the four combinations this is an input with the internal pull-up on. The pin is not driven as an output yet.
> After both lines: `DDB5` = 1 and `PB5` = 1, so PB5 is an output that drives Vcc.
> The end state is the same as with the slide's order. The slide's order is: first the direction (`DDRx`), then the value (`PORTx`).

## 5. Two steps forward, one step back (slides 9-10)
![[cmpe453_lecture_03_1_lecture3_1_p009.jpg]]
![[cmpe453_lecture_03_1_lecture3_1_p010.jpg]]

**Notes.** Task: 8 LEDs on port D, one lit at a time, moving "two steps forward, one step backward". Each LED is wired pin → 1 kΩ resistor → LED → GND, so a 1 in `PORTD` lights it. Current: $(5-2)/1000=3$ mA.

```c
#include <avr/io.h>
#include <util/delay.h>
#define DELAY 400
void blinkLEDs(uint8_t byte)
{
    PORTD = byte;
    _delay_ms(DELAY);
}
int main(void)
{
    DDRD = 0xFF;
    while (1) {
        blinkLEDs(0b00000001);
        blinkLEDs(0b00000010);
        blinkLEDs(0b00000001);
        blinkLEDs(0b00000010);
        blinkLEDs(0b00000100);
        blinkLEDs(0b00000010);
        /* ... the same pattern up to ... */
        blinkLEDs(0b01000000);
        blinkLEDs(0b10000000);
    }
    return 0;
}
```

The lit bit goes 0, 1, 0, 1, 2, 1, 2, 3, 2, 3, 4, ... up to 7. One pass has $2+6\cdot3+2=22$ calls and takes $22\times400$ ms = 8.8 s. PD0 and PD7 are lit 2 times per pass, PD1-PD6 3 times. Call $k$ starts at $(k-1)\cdot$`DELAY`.

> [!example] Which LED is on at t = 3.0 s?
> $3000/400=7.5$, so 7 calls are over and call 8 is running. Call 8 writes `0b00001000`: **PD3**.

> [!warning] Watch out
> After PD7 the light jumps back to PD0, it does not walk back. On the Uno PD0 and PD1 are also RX/TX of the USB link: if uploading fails, unplug those two wires.

> [!question]- Check (slide 9): The 1 kΩ resistors are replaced by 220 Ω resistors. The LED still takes about 2 V. How much current flows through a lit LED? Is it below the 20 mA that a pin is normally loaded with?
> Voltage across the resistor: the pin gives 5 V, the LED takes about 2 V, so $5-2=3$ V.
> Ohm's law: $I = V/R = 3/220 \approx 0.0136$ A $= 13.6$ mA.
> Yes, 13.6 mA is below 20 mA. It is about 4.5 times the 3 mA of the slide's 1 kΩ circuit ($1000/220\approx4.5$), so the LED is brighter.
> Only one LED is lit at a time in this program, so this is also the total LED current.

> [!question]- Check (slide 10): `DELAY` is 400. Which LED is on at $t = 6.1$ s after the first call starts, and which byte did the program write to `PORTD` for it?
> Find the call: $6100/400=15.25$, so 15 calls are over and call 16 is running (from $15\times400=6000$ ms to $16\times400=6400$ ms).
> The lit bit goes 0, 1, 0, 1, 2, 1, 2, 3, 2, 3, 4, 3, 4, 5, 4, 5, ... The 16th entry is 5.
> Call 16 is `blinkLEDs(0b00100000);`, so `PORTD` = `0b00100000` = `0x20` and **PD5** is on.

## 6. Exercises 1 to 3 (slides 11-13)
![[cmpe453_lecture_03_1_lecture3_1_p011.jpg]]
![[cmpe453_lecture_03_1_lecture3_1_p012.jpg]]
![[cmpe453_lecture_03_1_lecture3_1_p013.jpg]]

**Notes.** **Exercise 1**: show the count 0 to FFH on LEDs on port B.

```c
DDRB = 0xFF;             //Port B is output
while (1)
{
    PORTB = PORTB + 1;
}
```

`PORTB` is 8 bits, so after `0xFF` it wraps to `0x00`. Without a delay one step takes 5 cycles, a full count $256\times5=1280$ cycles = 80 µs at 16 MHz: too fast to see. Add `_delay_ms(250);`.

**Exercise 2**: get a byte from port B and send it to port C.

```c
unsigned char temp;
DDRB = 0x00;             //Port B is input
DDRC = 0xFF;             //Port C is output
while (1)
{
    temp = PINB;
    PORTC = temp;
}
```

**Exercise 3**: read port C. If the byte is less than 100 send it to port B, otherwise to port D.

```c
DDRC = 0;                //Port C is input
DDRB = 0xFF;             //Port B is output
DDRD = 0xFF;             //Port D is output
unsigned char temp;
while (1)
{
    temp = PINC;         //read from PINC
    if (temp < 100)
        PORTB = temp;
    else
        PORTD = temp;
}
```

99 goes to port B, 100 goes to port D. The port that is not written keeps its old value.

> [!warning] Watch out
> - Slide 13's comment says "read from PINB". The code reads `PINC`, which is correct.
> - `if (temp = 100)` assigns and is always true. Compare with `==`.
> - Real chip: port C has no PC7, so in Exercise 2 bit 7 is lost (`0xFF` appears as `0x7F`). Unconnected input pins float. Use pull-ups (`PORTB = 0xFF;`).

> [!question]- Check (slide 11): Exercise 1 gets `_delay_ms(100);` after the increment. How long does one full count from `0x00` to `0xFF` take? For how long is the LED on bit 7 on during one full count?
> One full count has 256 values, each shown for 100 ms: $256\times100=25600$ ms $=25.6$ s.
> Bit 7 is 1 for the values `0x80` to `0xFF`, that is 128 to 255. These are $255-128+1=128$ values.
> Time with bit 7 on: $128\times100=12800$ ms $=12.8$ s, the second half of the count.
> On a Uno this LED cannot be seen, because PB7 is a clock pin there. The answer is for the register bit.

> [!question]- Check (slide 12): Find the bug. In Exercise 2 a student writes `temp = PORTB;` instead of `temp = PINB;`. The switches on port B give `0xA5`. What appears on port C?
> Port C shows `0x00`, whatever the switches do.
> `PORTB` holds what the program wrote into it. The program never writes `PORTB`, so it still has its default value 0. The pin levels `0xA5` are only visible in `PINB`.
> Fix: read the input from `PINB`.

> [!question]- Check (slide 13): In Exercise 3 `PORTB` and `PORTD` start at `0x00`. `PINC` reads `0x50`, then `0x7F`, then `0x63`. What do `PORTB` and `PORTD` hold after each of the three passes?
> Convert each byte to decimal and compare with 100.
> Pass 1: `0x50` $=5\times16+0=80$. $80<100$, so `PORTB = 0x50`. `PORTD` stays `0x00`.
> Pass 2: `0x7F` $=7\times16+15=127$. $127<100$ is false, so `PORTD = 0x7F`. `PORTB` keeps `0x50`.
> Pass 3: `0x63` $=6\times16+3=99$. $99<100$, so `PORTB = 0x63`. `PORTD` keeps `0x7F`.
> The port that is not written in a pass keeps its old value.

## Key formulas and terms
| Term | Meaning / formula |
|---|---|
| Program shape | preamble, then `main`: configuration once, `while(1){...}` |
| `DDRx` | direction, 1 = output, 0 = input, default 0, bits `DDxn` |
| `PORTx` | output value, 1 = Vcc, 0 = GND, default 0, bits `Pxn`. On an input pin 1 = pull-up |
| `PINx` | pin levels, read only (slide) |
| Output in 2 steps | 1) `DDRx = mask;` 2) `PORTx = value;` |
| All outputs | `DDRD = 0xFF;` = `0b11111111` = `255` |
| PC3 and PC6 | `PORTC = 0b01001000;` = `0x48` = `(1<<PC6)\|(1<<PC3)` |
| Ports of the 328P | B: PB0-PB7, C: PC0-PC6, D: PD0-PD7. On the Uno PB6/PB7 (clock), PC6 (reset), PD0/PD1 (USB serial) are special |
| Two steps fwd, one back | 22 calls × 400 ms = 8.8 s per pass |

## Check yourself
> [!question]- 1. Which register do you use to (a) make PB2 an output, (b) see whether a button on PD3 is pressed, (c) switch on an LED on PC1?
> (a) `DDRB` (bit `DDB2`). (b) `PIND` bit 3, not `PORTD`. (c) `PORTC` bit `PC1`.

> [!question]- 2. Make PB0-PB3 outputs and PB4-PB7 inputs, then drive PB1 and PB2 high.
> `DDRB = 0b00001111;` (`0x0F`), then `PORTB = 0b00000110;` (`0x06`). Bits 4-7 of `PORTB` stay 0, a 1 there would turn on pull-ups.

> [!question]- 3. After `DDRD = 0xC3;` and `PORTD = 0x41;`, what does each pin do?
> `DDRD` = `0b11000011`, `PORTD` = `0b01000001`. PD7 out low, PD6 out high, PD5-PD2 floating inputs, PD1 out low, PD0 out high.

> [!question]- 4. In the two-steps program `DELAY` is 250. How long is one pass? How often is PD4 lit?
> $22\times250=5500$ ms = **5.5 s**. PD4 is lit **3 times** (calls 11, 13, 15).

> [!question]- 5. Starting from 0, what is `PORTB` after 300 runs of `PORTB = PORTB + 1;`?
> $300\bmod256=44=$ **`0x2C`** = `0b00101100`. On the Uno: PB5 (D13), PB3 (D11), PB2 (D10) are on.

> [!question]- 6. Exercise 2 on an ATmega328P with all port B inputs at 1: what appears on port C?
> `PORTC = 0xFF`, but there is no PC7, so the pins show `0b01111111` = **`0x7F`**.
