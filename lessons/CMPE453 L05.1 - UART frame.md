# CMPE 453 · Lecture 5.1 · Serial communication: the UART frame

> [!summary] In short
> - Serial = the bits of a byte go one after the other on one wire. Three protocols in the course: USART, SPI, I2C.
> - 8N1 frame: line idle at 1, start bit 0, 8 data bits **LSB first**, stop bit 1. That is 10 line bits per byte.
> - Decode: drop start and stop, reverse the 8 data bits.
> - Baud = line bits per second. Bit time = 1/baud (9600 baud: 104.2 µs, 960 bytes/s).
> - There is no clock wire. Both sides must agree on the baud rate and the frame.
> - On the Uno: RxD = PD0 = D0, TxD = PD1 = D1. TX goes to RX, GND to GND.

## 1. Serial communication and its three protocols (slides 2-3)
![[cmpe453_lecture_05_1_lecture5_1_p002.jpg]]
![[cmpe453_lecture_05_1_lecture5_1_p003.jpg]]

**Notes.** In serial communication the sender puts the bits on **one** data line, one at a time. Parallel would use 8 wires. USART is the simplest way to connect an AVR to a computer or to another microcontroller.

| | UART | SPI | I2C |
|---|---|---|---|
| Wires (plus GND) | TX, RX | MOSI, MISO, SCK, SS | SDA, SCL |
| Clock wire | no (agreed baud rate) | yes (SCK) | yes (SCL) |

**Simplex**: one direction only. **Half duplex**: both directions, one at a time on a shared wire. **Full duplex**: both directions at the same time on separate wires. UART has a TX and an RX wire, so it is full duplex.

**Notes.** Elif has a button, Damla sees an LED at the other end of one wire. The pull-up $R_1$ to 5 V keeps the line at 1 while nobody presses. The rules they agree on:
- Button pressed = 0 = LED off. No press = 1 = LED on.
- Send the **LSB first** (bit 0, the rightmost digit).
- Speed: 1 press per second, so one bit lasts 1 s.
- Start bit = 0. Stop bit = 1.

Elif sends 12 = `00001100`. First the start bit 0 (slide 6: Rcvd-bits = `0`). Then the data bits from the right: 0, 0, 1, 1, ... Damla writes each bit down as it arrives: `00`, `000`, `0001`.

The start bit is needed because the line rests at 1: a first data bit 1 would look like "nothing happened". The 1-to-0 change marks the moment to start counting bit times.

## 3. The rest of the frame and decoding (slides 10-15)
![[cmpe453_lecture_05_1_lecture5_1_p010.jpg]]
![[cmpe453_lecture_05_1_lecture5_1_p011.jpg]]
![[cmpe453_lecture_05_1_lecture5_1_p012.jpg]]
![[cmpe453_lecture_05_1_lecture5_1_p013.jpg]]
![[cmpe453_lecture_05_1_lecture5_1_p014.jpg]]
![[cmpe453_lecture_05_1_lecture5_1_p015.jpg]]

**Notes.** After the last data bit Elif sends the stop bit 1. Damla has received `0001100001`:

| Start | d0 | d1 | d2 | d3 | d4 | d5 | d6 | d7 | Stop |
|---|---|---|---|---|---|---|---|---|---|
| 0 | 0 | 0 | 1 | 1 | 0 | 0 | 0 | 0 | 1 |

Decode: flip the order (`1000011000`), drop stop and start, the data bits are `00001100` = 12.

A **frame** is what goes on the line for one byte. With **8** data bits, **N**o parity and **1** stop bit it is called **8N1**: $1+8+1=10$ bits per byte.

The **baud rate** is the number of bits per second on the line. One bit lasts 1/baud. Elif: 1 baud. The Uno usually uses 9600 baud: $1/9600\ \text{s}=104.2$ µs per bit.

**Asynchronous** means no clock wire. It works because both sides agreed on the bit time in advance and the start bit says when to start counting. If baud rate or frame format differ, the receiver samples the wrong bits and shows garbage.

Bit $i$ of a byte in C: `(data >> i) & 1`.

> [!warning] Watch out
> - The slide's "flip" **reverses the order** (`0001` → `1000`). C's `~` inverts every bit. Decoding a frame never inverts.
> - Baud counts bits, not bytes. At 8N1 one byte costs 10 bits, so 9600 baud carries 960 bytes/s, not 1200.

## 4. The USART in the ATmega328P and on the Uno (slides 16-18)
![[cmpe453_lecture_05_1_lecture5_1_p016.jpg]]
![[cmpe453_lecture_05_1_lecture5_1_p017.jpg]]
![[cmpe453_lecture_05_1_lecture5_1_p018.jpg]]

**Notes.** Slide 16 is the USART block diagram from the datasheet. Three parts:
- **Clock generator**: the baud rate generator divides the clock by a number from `UBRR0`. This sets the bit time.
- **Transmitter**: `UDR0` (transmit) and the transmit shift register, output on TxD.
- **Receiver**: the receive shift register and `UDR0` (receive), input on RxD.
- Control and status registers: `UCSR0A`, `UCSR0B`, `UCSR0C`.

The USART can run synchronously (with a clock on the XCK pin) or asynchronously. Asynchronous mode is a UART, and that is what the course uses.

Wiring (slide 18): computer → USB → USB/serial adapter → AVR chip.
- RxD = **PD0** (Uno D0, chip pin 2). TxD = **PD1** (Uno D1, chip pin 3).
- TX of one side goes to RX of the other. The wires **cross**.
- Both sides share **GND**.
- The TX and RX LEDs on the Uno blink while data flows.

On the PC the Uno is a serial port (`/dev/ttyUSB0` or `/dev/ttyACM0`). Open a terminal at the program's baud rate, 8N1. Opening the port resets the Uno. Close the terminal before flashing.

> [!warning] Watch out
> - `UDR0` is one name for two buffers. Writing `UDR0 = x;` fills the transmit buffer. Reading `x = UDR0;` gives the last received byte, not what you wrote.
> - Keep D0 and D1 free in UART programs. The USB adapter also uses them for flashing.
> - "Pin 2" and "Pin 3" on slide 18 are legs of the chip, not the Uno's D2 and D3.
> - Slide 18 writes "dublex" for duplex.
> - Garbage characters almost always mean a baud-rate or `F_CPU` mismatch.

## Key formulas and terms
| Term | Meaning / formula |
|---|---|
| Frame 8N1 | idle 1, start bit 0, 8 data bits LSB first, stop bit 1: 10 bits per byte |
| Decode | drop start and stop, reverse the 8 data bits, convert |
| Baud | line bits per second, bit time = 1/baud (9600: 104.2 µs, 960 bytes/s) |
| Asynchronous | no clock wire, both sides agree on baud and frame |
| Simplex / half / full duplex | one direction / both but one at a time / both at once |
| Bit $i$ in C | `(data >> i) & 1` |
| Hardware | `UBRR0` sets the bit time, `UDR0` write = send, read = received byte, `UCSR0A/B/C` control |
| Pins | RxD = PD0 (D0), TxD = PD1 (D1), cross TX and RX, common GND |

## Check yourself
> [!question]- 1. Write the 8N1 line bits for the number 5.
> 5 = `0000 0101`. LSB first: `10100000`. With start and stop: **`0 10100000 1`**.

> [!question]- 2. A receiver records the frame `0110100101` (first bit first). Which byte and character was sent?
> Drop start and stop: `11010010`. Reverse: `0100 1011` = **`0x4B`** = 75 = `'K'`.

> [!question]- 3. Elif sends the byte 200 at 1 bit per second. How long does it take, and what does Damla write down?
> 10 bits × 1 s = **10 s**. 200 = `1100 1000`, LSB first `00010011`, with start and stop **`0000100111`**.

> [!question]- 4. Why is a start bit needed, and why must it be 0? Why is there a stop bit 1?
> The line rests at 1, so only a 0 is a change the receiver is sure to see. It marks when to start counting. The stop bit returns the line to 1, so the next start bit is again a visible 1-to-0 change.

> [!question]- 5. A loop prints "Hello\r\n" (7 characters) at 9600 baud, 8N1. How long is one line and how many lines per second fit?
> $7\times10=70$ bits. $70/9600\ \text{s}=$ **7.29 ms**. $960/7=137.1$, so **137** whole lines per second.

> [!question]- 6. A student wires TX to TX and RX to RX between two Unos. What happens?
> Both transmitters drive the same wire and both receivers listen to a wire nobody drives. No byte arrives. TX must meet RX, plus GND to GND.
